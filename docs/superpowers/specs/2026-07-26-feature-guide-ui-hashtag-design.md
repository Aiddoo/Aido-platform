# 기능 가이드 UI 및 해시태그 표기 개선 설계

## 배경

1.8.0 기능 가이드는 메모 AI, 친구 검색, 드래그 정렬, 할 일 생성을 한곳에서
알려주지만, 카드 안의 미리보기가 실제 앱 화면과 충분히 닮지 않았다. 특히 친구
검색은 제품에서 사용하는 해시태그를 `Aido ID`로 안내하고, 결과 행은 `@` 접두어를
사용해 용어와 시각 표현이 어긋난다.

## 목표

- 기능 가이드의 네 미리보기를 실제 화면의 축약판으로 만든다.
- 사용자 대상 용어를 `해시태그`로 통일한다.
- 기존 서버 API와 1.7.0 클라이언트가 사용하는 `userTag` 계약은 그대로 유지한다.
- UI 변경 때문에 새로운 데이터 조회, 캐시 키, 네트워크 요청을 추가하지 않는다.

## 해시태그 규칙

- 저장 및 API 전송 값은 기존과 동일한 8자리 영문 대문자·숫자 문자열이다.
- 서버 생성기는 혼동하기 쉬운 `0`, `O`, `1`, `I`, `L`을 만들지 않는다.
- 사용자에게 식별자를 보여주는 곳에서는 `#`을 붙여 해시태그임을 명확히 한다.
- 직접 친구 추가 입력과 API에는 접두어 없는 8자리 원본을 계속 사용한다.
- 클립보드에도 접두어 없는 원본을 복사해 1.7.0 클라이언트에 붙여넣을 수 있게 한다.
- 이름 검색과 기존 태그 검색 요청 형식은 바꾸지 않는다.

## UI 설계

`FeatureDiscoverySheet`의 캠페인·스크롤·CTA 구조는 유지하고 미리보기만 별도
컴포넌트로 분리한다. 미리보기는 실제 화면 컴포넌트를 직접 마운트하지 않는다.
실제 컴포넌트는 쿼리, 폼, 라우터, 드래그 상태에 결합되어 있어 바텀시트 안에서
재사용하면 네트워크 요청과 중첩 오버레이가 생길 수 있기 때문이다.

대신 실제 화면과 동일한 디자인 토큰, 공용 UI 요소, 아이콘과 배치를 사용한다.

- 메모 AI: 메모 본문과 로봇 액션, 변환된 할 일 행을 한 흐름으로 보여준다.
- 친구 검색: 검색 입력창, 프로필 아바타, 이름, `#` 해시태그, `추가` 버튼을 실제
  검색 결과 행과 같은 구조로 보여준다.
- 드래그 정렬: 카테고리 설정의 색상 점, 카테고리 이름, 오른쪽 정렬 핸들을 그대로
  축약한다.
- 할 일 생성: 실제 생성 바텀시트의 제목 입력, 날짜·시간·반복·카테고리 칩,
  전송 버튼을 축약한다. 실제 화면에 없는 별도 `AI 추천` 생성 방식을 안내하지 않는다.

HeroUI Native를 이미 쓰는 화면 요소의 시각 언어를 따르고, 앱의 `shared/ui`
primitive를 우선 재사용한다. 미리보기 자체는 동작하지 않는 설명용 영역이며 CTA만
기존처럼 실제 기능 화면으로 이동한다.

## 호환성과 성능

- API 경로, 요청·응답 Zod 스키마, DB 스키마, 캐시 키를 변경하지 않는다.
- 기능 가이드 렌더링 중 쿼리나 mutation을 추가하지 않는다.
- 기존 캠페인 노출·재진입·분석 이벤트·CTA 라우팅은 변경하지 않는다.
- `#`은 표시 전용으로 붙이며 서버에 보내는 값에는 포함하지 않는다.

따라서 1.7.0 클라이언트의 파싱과 동작에는 영향이 없고, 1.8.0에서는 안내 문구와
미리보기의 정확도만 높아진다.

## 테스트

- 해시태그 표시 formatter의 정상 값과 중복 접두어 방지를 단위 테스트한다.
- 기존 기능 가이드 테스트를 새 문구와 실제 화면형 미리보기 기준으로 갱신한다.
- 기능 가이드의 CTA 라우팅, 캠페인 상태, 분석 서비스 테스트는 기존 범위를 유지한다.
- `pnpm typecheck && pnpm lint`와 모바일 대상 테스트를 통과시킨다.
- iOS Simulator에서 가이드 바텀시트의 네 카드와 친구 검색 이동 화면을 육안 대조한다.
