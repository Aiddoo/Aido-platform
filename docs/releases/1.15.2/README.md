## 요약

- **쓰던 글**: 수정 폼 5곳(메모·할 일·카테고리·하위 항목·이름)이 서버 값을 다시 받아도 고치던 칸, 저장할 변경, 칸 오류를 지킨다. 메모 저장이 시간 초과된 뒤 다시 저장해도 메모는 하나만 생긴다.
- **계정 경계**: 계정을 바꾼 직후의 결제·복원은 결제 SDK 로그인이 끝난 뒤에만 연다. 탈퇴하면 계정별 기기 기록 5종도 지운다. 로그아웃·탈퇴·세션 만료 때 알림 센터의 알림을 지운다. 읽지 못한 저장소는 비어 있다고 보지 않는다(키체인이 잠긴 실행, 오프라인이라 보내지 못한 탈퇴).
- **오류 안내**: 5xx의 서버 코드를 읽어 원인에 맞는 문구를 보인다. 오류 화면의 문의하기에 진단 코드·오류 코드·요청 ID 초안을 넣는다. 예상하지 못한 실패는 빠짐없이 Sentry에 보고한다.
- **주차**: 그 주의 가운데 날(일요일 시작 주는 수요일, ISO 주는 목요일)이 속한 달의 몇째 주로 센다. 달력·위젯·성취·리포트(서버 라벨 포함)가 같다.
- **넓은 화면**: iPadOS 26+ 탭 사이드바를 열어도 목록 칸이 짓눌리지 않는다. 창 크기를 바꾸는 동안 달력 재마운트가 8번에서 1번으로 줄었다.
- **성능**: 음성 파형과 날씨 장면에서 쌓이던 Skia 객체를 놓는다. 저사양 Android에서는 무더위 아지랑이 셰이더를 끈다.
- **접근성**: 아이콘이 앱 글꼴 단계를 따르고, 기본 단계는 픽셀이 같다. 메모 고정·삭제와 음성 메모 삭제를 스크린리더 동작으로도 할 수 있다.
- **서버**: 응답 모양은 추가만 한다. 출시 계약 지문은 그대로다. migration은 셋이다: `memo_idempotency_key`(칸·색인 추가), `drop_push_daily_budget`(아무 코드도 쓰지 않는 빈 테이블만 확인 뒤 삭제), `retire_unused_columns`(실행 SQL 없음, 1.16.0에 지울 칸을 스키마에서만 뺌). 배포 전 RDS 스냅숏을 뜨고 서버를 먼저 배포한다.
- **네이티브**: Expo 58.0.23 → 58.0.24와 패키지 26개 패치에 네이티브 변경이 있어 스토어 빌드로만 나간다. <!-- d4a0d8c4b -->
- **업데이트 안내 대화상자**: 이번에 만들지 않는다(사용자 결정, 다음 버전).

## 사용자에게 보이는 수정

### 데이터 안전

**결제 귀속**

- 계정 A에서 로그아웃하고 B로 로그인한 직후 결제하면, SDK가 아직 A(로그아웃 실패·15초 시간 초과)이거나 익명일 수 있었다. 그러면 B의 결제가 A의 구독으로 잡히거나 어느 계정에도 반영되지 않았다. 복원도 B의 구매를 A로 옮길 수 있었다. 이제 결제·복원은 `PurchasesSession.waitForSignedInUser`가 돌려준 계정이 있을 때만 결제 창을 연다. 없으면 기존 "결제를 마치지 못했어요 / 스토어에 연결하지 못했어요" 다이얼로그로 막는다. <!-- 1f3f506f1 -->
- RevenueCat logIn·logOut이 겹치면 늦게 끝난 쪽 사용자로 남던 것을 하나씩 차례로 돌린다. 멈춘 SDK 호출은 15초에서 끊는다. 스토어 로그인은 계정 id가 바뀔 때만 한다. <!-- 5a71a38b5 4ac3e91c7 -->
- 결제·복원 버튼을 같은 프레임에 두 번 눌러도 스토어 창은 한 번만 열린다. 구독 시작 화면의 "완료"를 연타하면 `back()`이 두 번 돌아 페이월 아래 화면까지 닫히던 것을 `useGoBack`으로 막는다. <!-- 357b09647 5b7787438 -->
- 로그인 뒤 분석 ID·구독자 속성 동기화가 멈춰도 결제·복원 버튼이 끝없이 돌지 않는다. 두 동기화를 각각 15초에서 끊는다. 계정을 바꾼 로그인이 실패·시간 초과였으면 다시 로그인을 기다려 첫 탭에 결제 창을 연다. <!-- f148d7419 -->

**탈퇴·로그아웃 정리**

- 탈퇴 정리 등록부가 계정별 기기 기록 5종(리뷰 요청, 시작 체크리스트 진행, 초대 배너 닫음, 발자국 축하, 출시 소개 귀속)을 빠뜨렸다. 그래서 탈퇴한 사람의 기록과 id가 MMKV에 남았다. 다섯 저장소를 등록부에 더했다. 저장 스키마를 모두 읽어 새 계정 범위 값이 등록되지 않으면 실패하는 완전성 테스트도 둔다. <!-- 9097c78fd -->
- 탈퇴 요청이 서버에 닿았는데 응답을 받지 못하면, 다음 401이 세션 만료로 끝나 초안·녹음·안내 기록이 남았다. 이제 결과를 모르는 탈퇴를 기억했다가 이어지는 만료를 로그아웃처럼 정리한다. 계정 id는 요청 전에 확보한다. <!-- 9e09987a4 -->
- 로그아웃·탈퇴 뒤 화면 밖에서 끝난 녹음이나 초안 자동 저장이 지운 계정 값을 되살리지 않는다(로그아웃 세대 `SignOutEpoch`). 세션 만료는 같은 사람이 이어 쓰므로 초안·녹음을 남긴다. <!-- 5a71a38b5 -->
- 암호화 저장소를 열지 못한 실행의 로그아웃 정리를 다음 실행에서 마친다. 그래서 이전 계정의 조회 캐시를 복원하지 않고, 다음 계정의 초안·녹음을 지우지 않는다(QA 1_전 #10 후보). <!-- e14299d51 -->
- 로그아웃 이유별 정리를 `match().exhaustive()`로 고른다. 이유가 새로 생겼는데 정리가 빠지면 컴파일이 막는다. <!-- 4ee45ee34 -->
- 재부팅 뒤 잠금 해제 전에 깨어난 실행은 암호화 초안 저장소를 열지 못해 초안이 0개로 보였다. 같은 실행에서 로그인되면 녹음 정리가 이것을 "가리키는 초안 없음"으로 읽어 1시간 지난 말로 메모 녹음을 지웠다(1.15.1부터). 이제 저장소를 연 실행에서만 녹음을 정리하고, 못 연 실행의 초안은 그 실행 동안 메모리에 둔다(앱을 끄면 사라진다). <!-- 44b007b5d -->
- 비행기 모드처럼 보내기 전에 오프라인이던 탈퇴는 결과 모르는 탈퇴로 남기지 않는다. 결과 모르는 탈퇴도 인증 요청 성공·탈퇴 재시도 결과·다시 로그인으로 계정이 살아 있다는 증거가 오면 잊는다. 그래서 살아 있는 계정의 초안·녹음·안내 기록을 지우지 않는다. <!-- 7949f7933 -->

**쓰던 글 지키기**

- 메모 편집·할 일 고치기·카테고리 고치기·하위 항목 고치기·이름 고치기 폼에 적용된다. 열어 둔 사이 서버 값이 바뀌면 고치지 않은 칸만 새 값으로 바꾼다. 고치던 칸, 저장할 변경, 칸 오류는 지킨다(`SERVER_VALUES_RESET_OPTIONS`: keepDirtyValues·keepDirty·keepErrors). 전에는 옛 글로 덮어 저장할 수 있었다. <!-- a5557189c f4fcad3a9 feabe06ed -->
- 메모 저장이 시간 초과된 뒤 다시 저장하면 메모가 2개 생겼다(둘 다 201, QA 1_전 #1). 이제 새 메모 저장마다 `Idempotency-Key`를 보낸다. 응답을 받지 못한 키는 글과 함께 초안에 남겨, 앱을 다시 켠 뒤에도 같은 키를 보낸다. 글을 고치면 새 키를 쓴다. <!-- 17f1f52e2 d8390652e -->
- 메모 글 수정과 고정이 겹쳐 응답 순서가 바뀌면 고정이 풀려 보였다. 이제 마지막 쓰기가 서버 값으로 맞춘다. <!-- 3cd001881 -->
- 하위 항목 추가가 실패해도 함께 진행 중인 다른 추가의 완료 값을 되돌리지 않는다. 다른 쓰기가 진행 중이면 목록을 다시 받지 않는다. 반복 묶음 쓰기는 진행 중인 체크를 덮지 않는다. <!-- 5bb615a00 bf557d192 6f223b3a7 -->
- 확인 다이얼로그는 요청이 실패하면 닫히지 않고 남는다. 다시 누르거나 취소할 수 있다. 카테고리·메모 삭제, 차단과 7곳(소셜 계정 탈퇴, 계정 연결 해제, 비밀번호 탈퇴, 친구 끊기, 초대 링크 새로 만들기, 댓글 삭제, 차단 해제), 여러 날 할 일 삭제, AI 데이터 제공 철회가 그렇다. 친구 끊기·댓글 삭제는 행이 낙관적으로 빠져도 다이얼로그가 남도록 목록·댓글 세션에서 띄운다. <!-- 7ed7cc637 37311c4a5 279a4eb85 61bebcc1a -->
- 시간 피커 두 벌을 `TimeSpinner` 하나로 모았다. 서머타임 시작일(뉴욕 2026-03-08)에 02:30이 03:30이 되던 것과, 앱 시간대와 기기 시간대가 다르면 시각이 바뀌던 것을 고친다. <!-- 6d4dc1777 -->
- 공백만 쓴 이름(가입·프로필·카테고리)은 폼이 저장 버튼을 켜지 않고, 서버도 거절한다(QA 1_전 #4). <!-- 69f503791 c5c5d5360 1b6e97072 -->

### 알림

- 로그아웃·탈퇴·세션 만료 때 알림 센터에 도착한 알림을 지운다. 공용 기기에서 다음 계정이 앞 계정의 알림 문구를 보지 않게 하려는 것이다. 로그인한 적 없는 시작과 판정 실패에서는 지우지 않는다. <!-- 09d08f250 -->
- 알림 권한 창이 닫히자마자 버튼·토글이 풀리고 안내 화면이 닫힌다. 대상은 첫 실행 알림 안내 [계속], 설정 알림 토글, 권한 다시 묻기 카드, 초대 환영 시트다. 전에는 푸시 토큰 발급(최대 15초)과 기기 등록 PUT이 끝날 때까지 기다렸다. <!-- 9a5d65e94 -->
- 혜택·소식 알림 제안 시트는 동의를 기록하는 동안 끌어 내려도 닫히지 않는다. 로그아웃·언마운트 뒤에는 시트를 띄우거나 답을 남기지 않는다. <!-- a2eb7366b 37b4dc23a -->
- 로그아웃·언마운트 뒤에 끝난 푸시 응답 처리나 기기 보고는 안내를 띄우거나 기록을 남기지 않는다. <!-- b08c12de8 ee7cbf8aa -->
- 좁은 화면 알림 목록에서 읽은 할 일·콕 알림 행을 길게 누르면 목적지를 미리 본다. <!-- 012bdecb4 -->
- 콕 상세·감사 시트는 `NUDGE_1105`·`NUDGE_1111`일 때만 "콕을 볼 수 없어요"를 보인다. 그 밖 404는 일반 오류 화면(다시 시도)이다. 보낸 콕 목록은 1105와 1111을 모두 꺼짐으로 읽는다. <!-- 58bd037b9 -->
- 날씨를 보는 중에 날씨 푸시·위젯·링크로 다시 열면, 같은 날씨 화면을 하나 더 쌓지 않고 있던 화면으로 돌아간다(`dangerouslySingular`). <!-- 7f0ef1c3d -->
- 알림 목적지는 서버 `navigation` 하나로 계산한다. 옛 필드 길과 옛 댓글 route는 지웠다. 그래서 서버 1.15.1 이상이 먼저 있어야 한다([호환](#서버-변경과-호환)). <!-- 515a73d4e df3153e40 -->

### 메모·AI

- 메모 AI 정리를 기다리다 편집기를 떠났으면 결과 화면으로 끌고 가지 않는다. 결과는 초안에 남는다. 그 메모에서 다시 누르면 차감 없이 바로 열린다. <!-- 4537c24b6 -->
- AI 업체 장애(`AI_1301`, 503)로 실패해도, 서버가 `charged: false`를 실으면 "차감되지 않아요" 설명을 붙인다. 말로 정리·빠른 말하기가 AI 장애가 아닌 5xx나 계약과 다른 응답으로 실패하면 "문제가 생겼어요"를 보인다. <!-- c400d1b8f c597d7b83 -->
- 메모 탭 카드는 탭을 바꾸거나 폭이 바뀌어도 옆에서 날아 들어오지 않는다(FlashList masonry). <!-- b2af0eed1 -->
- iOS에서 메모 카드·말로 남긴 메모 행을 길게 누르면 미리보기와 메뉴(열기·고정·삭제)가 뜬다. <!-- a1b4021b5 30df1927b -->
- 앞뒤 공백을 붙여 5000자를 넘긴 메모도 저장할 글(앞뒤 공백을 뺀 글)이 5000자 이하면 저장된다. <!-- c921cf07b -->
- 하위 항목 받아쓰기와 빠른 말하기가 칸에 옮긴 글자를 바로 검사한다. 전에는 받아쓴 글이 덮이거나, 저장 없이 닫힐 수 있었다. <!-- 0f1f99f57 64d8d6847 -->
- 5xx 응답의 서버 코드·details를 오류에 싣는다. 그래서 날씨 장애와 DB 과부하(`SYS_0005`)를 구분하고, 실패 토스트가 서버 코드의 카탈로그 문구를 보인다. <!-- 3d787f69a -->
- 오류 화면의 문의하기를 누르면 문의 화면이 첫 줄에 진단 코드·오류 코드·요청 ID를 담은 초안으로 열린다. 4xx 경계도 요청 ID를 담는다. <!-- 33c7e1418 556cc4c6a -->

### 달력·피드

- 주차를 그 주의 가운데 날이 속한 달의 몇째 주로 센다. 달력·위젯·성취·리포트가 같은 함수를 쓰고, 리포트 라벨은 서버도 같은 규칙이다. 올해가 아닌 주에는 연도를 붙인다. <!-- dcb6dbd8b 4a276ac60 -->
- 피드 달력 점을 달마다 고정 키로 받고 앞뒤 달을 미리 받아, 달을 넘겨도 점이 비지 않는다. <!-- 9bbe1d680 -->
- 날짜 피커는 탭 한 번에 Intl 포매터를 305번 부르던 것이 0번이 됐다. 반복 피커는 570번에서 25번이다(테스트로 셈). 반복 마지막 회차 계산은 하루씩 걷지 않고 간격으로 건너뛴다. 매주 월·목 기준 7.73ms에서 0.60ms가 됐다(Node --jitless, 365번 중앙값). <!-- ae767e3ce cb52a50cb -->
- 반복 안내와 시작 체크리스트가 `GET /v1/todos` 3번 대신 `GET /v1/todos/overview` 1번으로 읽는다. <!-- 0ad6756dd -->
- 카테고리 이름·색을 바꾸면 할 일 상세 제목 줄도 맞춘다. 콕을 보낸 뒤에는 그 상세의 콕 가능 여부를 서버 값으로 맞춘다. 내 피드를 당겨서 새로고침할 때 날씨를 기다리지 않는다. <!-- 3f257ff3f -->
- 친구 피드의 할 일 행에서 하위가 없는 행을 누르면 상세로 간다(연타해도 한 번). iOS에서 길게 누르면 미리보기와 메뉴가 뜬다. 메뉴는 [열기]이고, 오늘 끝나지 않은 할 일이면 [콕 찌르기]가 더해진다. <!-- b7b08dbfd 021373786 f26f41bbf -->
- 마이 > 친구 목록 행을 누르면 그 친구 피드로 간다. iOS에서 길게 누르면 메뉴(피드 보기·콕 찌르기·신고·차단)가 뜬다. <!-- 26dcc8d92 -->
- 친구 할 일 상세에서 차단하면 상세도 다시 받아 '볼 수 없음' 안내로 바뀐다. <!-- 51ab26a7e -->
- 콕 보내기나 신고하기를 같은 프레임에 두 번 눌러도 한 번만 보낸다. <!-- eb2b86135 2cfe96ca5 -->
- 친구를 지워도 목록이 일찍 끝나지 않는다. 답글 지우기 실패를 되돌릴 때 대표 답글 수를 두 번 늘리지 않는다. <!-- 123991244 77be0a4dd 6605d424b -->

### 날씨·음성 성능

- 음성 파형은 390pt 녹음 파형 기준 0.1초마다 네이티브 객체 162개를 놓지 않았다. 이제 경로 4개를 만들고 앞 4개를 바로 놓는다. 다시 그리는 Skia 경로는 공용 `useRebuiltPath`가 만들고, 날씨 물방울·번개도 같은 훅을 쓴다. <!-- efa07f79f 08969f9da 168efeabf -->
- 날씨 장면의 텍스처 훅은 마운트마다 만들던 PathBuilder 69개를 0개로 줄였다. 유리 물방울 30초 동안 10,424번 하던 Rect 할당도 0번이 됐다(Jest Skia stub 계수). <!-- ffd643abb -->
- 시간별 예보 칸은 시간이 바뀔 때만 다시 그린다. 24시간 예보에 1분 tick을 120번 주면 칸 렌더가 960번에서 16번이 됐다(Jest). <!-- 7704ae54b -->
- 메모리 3GB 미만 Android에서는 무더위 아지랑이 셰이더만 끈다. <!-- 0398cae1d -->
- 날씨 위치의 장소 이름 찾기와 위치 등록을 함께 시작한다. 10일 예보의 할 일 점은 리포트와 함께 받는다. 기기 위치 쿼리는 날씨 무효화에 휩쓸리지 않는다. <!-- 1abdea5a9 422adb1c0 7bfd6c180 -->
- 말로 남긴 메모 결과에서 탭을 바꿀 때 내용을 흐리게 띄우지 않는다. <!-- acaafc472 -->

- 루트 오류 화면 글자는 OS 글꼴을 최대로 키워도 혼자 커지지 않는다. <!-- 902b0a2c7 -->

### iPad·Mac·Duo 배치

- iPadOS 26+에서는 탭 사이드바가 탭 폭을 줄이지 않고 왼쪽 safe area inset(280pt)으로 온다. 그래서 사이드바를 열면 목록 칸이 120pt로 짓눌렸다. 이제 `PaneArea`가 SafeAreaProvider의 frame·inset으로 잰다. 칸은 칸 자리를 차지하는 inset(iPad 사이드바·Duo 레일)을 뺀 내용 폭으로 나눈다. Android 좌우 inset(시스템 바·컷아웃)은 계산에 넣지 않는다. <!-- 925d11834 -->
- Mac·iPad 창 크기를 바꾸는 동안 달력 쪽 목록을 미뤄 다시 만든다. dev build에서 3초 동안 잰 값이다. <!-- 7ebc04584 -->
  - 넓히기: 재마운트 8번 → 1번, 770ms → 227ms.
  - 좁히기: 재마운트 2번 → 1번, 271ms → 183ms.
- 제안 화면 아래 inset을 내용 padding으로 둔다. 스크롤이 홈 인디케이터 밑까지 이어진다.
- 칸 폭이 바뀐 곳은 [iPad·iPhone Duo 칸 배치](#ipadiphone-duo-칸-배치) 표에 있다.

## 서버 변경과 호환

서버(`@aido/server`)와 계약(`@aido/api`)의 버전은 `pnpm version-packages`가 앱 버전 1.15.2로 맞춘다. changeset 13개 가운데 minor가 4개다(`nudge-interaction-disabled-code`, `shared-contract-values`, `todo-overview`, `verify-resend-cooldown-details`). minor여도 버전 번호는 앱 버전을 따른다. <!-- b9f52f45b: verify-resend minor -->

### 응답 모양: 추가만

- **`NUDGE_1111` 추가(404)**: 콕 답장·감사 기능이 서버 설정으로 꺼졌다는 뜻이다. 문구는 "지금은 콕 답장과 감사를 사용할 수 없습니다."다. 전에는 "없는 콕"과 같은 `NUDGE_1105`였다. 답장·감사 API 5개의 404 문서에 더했다. <!-- 30801bb96 -->
  - `ReleasedAppNudgeErrorInterceptor`가 답장·감사 controller에서 출시 앱에 `NUDGE_1105`를 그대로 보낸다. 대상은 `X-App-Version`이 없거나 1.15.2보다 낮은 앱이다. 버전은 `RequestClientReader`로 읽는다(Controller에서 헤더를 직접 읽지 않는다).

### 배포 중 사용자 영향

- **응답**: 모양과 출시 계약 지문은 그대로다. 지운 테이블과 뺀 칸은 어느 응답에도 쓰이지 않는다.
- **잠금 대기**: 한 트랜잭션이라 memo 마이그레이션이 잡은 Memo 잠금은 DROP이 User 잠금을 얻을 때까지 이어진다. 앱 세션 `lock_timeout`이 5초라 그보다 오래 쥐면 Memo 요청이 503 `SYS_0005`가 된다. 앱 트랜잭션이 User를 쥔 채 Memo를 기다리면 교착이 되고, 앱 쪽이 끊기면 500이다. 그래서 DROP 마이그레이션은 잠금 대기를 0.5초로 줄였다(`deadlock_timeout` 1초보다 짧다). 못 잡으면 migrate가 먼저 물러나고 API는 바뀌지 않는다. 다시 실행하면 된다.
- **memo 색인**: `CREATE INDEX CONCURRENTLY`는 쓸 수 없다(migrator가 한 트랜잭션이다). 새 칸이 모두 NULL이라 부분 색인 항목은 0개이고 Memo를 한 번 훑기만 한다. 사용자 약 415명 규모에서는 ms다. 아래 D가 10만 행을 넘으면 색인을 따로 나눈다.
- **로컬 확인(PG 16.15, 테스트 setup DB)**: DROP이 User에 AccessExclusiveLock을 거는 것을 `pg_locks`로 봤다. `push-daily-budget-drop` 통합 테스트는 되돌리기 SQL로 테이블을 되살린 뒤 두 경우를 본다. 행이 있으면 P0001로 실패하고 트랜잭션이 되돌아간다. 비어 있으면 지운다. `retired-columns` 통합 테스트는 세 칸이 DB에 남고 칸 없이 넣어도 채워지는지 본다.

### 운영 읽기 전용 확인

배포 전(머지 전 한 번, 배포 직전 한 번):

```sql
-- A. 지울 테이블이 비었는지. 0이 아니면 drop_push_daily_budget 커밋을 빼고 배포한다
SELECT count(*) AS rows, min("localDate") AS first_day, max("localDate") AS last_day
FROM "PushDailyBudget";

-- B. 1.16.0에 지울 칸. 이번 배포에는 영향 없고, 0이 아니면 1.16.0에서도 남긴다
SELECT count(*) AS users,
       count(*) FILTER (WHERE "twoFactorEnabled") AS two_factor_enabled,
       count("twoFactorSecret") AS two_factor_secret_set
FROM "User";
SELECT count(*) AS subscriptions, count("dataRetentionUntil") AS data_retention_until_set
FROM "Subscription";

-- C. assignedAt을 남기는 근거: 늘 차 있고 startedAt과 다르다
SELECT count(*) AS assignments,
       count("assignedAt") AS assigned_at_set,
       count(*) FILTER (WHERE "startedAt" IS DISTINCT FROM "assignedAt") AS assigned_at_unique
FROM "RetentionExperimentAssignment";

-- D. memo 마이그레이션 크기
SELECT count(*) AS memos, pg_size_pretty(pg_total_relation_size('"Memo"')) AS memo_size FROM "Memo";

-- F. 1.15.0 백필 결과(이번 출시 범위 밖, 계약 nullable 판단용)
SELECT count(*) FROM "Todo" WHERE "scheduledTime" IS NOT NULL AND "scheduledLocalTime" IS NULL;
```

```sql
-- E. 2초 넘게 열린 트랜잭션이 없어야 한다. 교착 검사 시간은 1s여야 한다
SELECT pid, state, now() - xact_start AS xact_age, wait_event_type, left(query, 60) AS query
FROM pg_stat_activity
WHERE datname = current_database() AND xact_start IS NOT NULL
  AND now() - xact_start > interval '2 seconds' AND pid <> pg_backend_pid()
ORDER BY xact_start;
SHOW deadlock_timeout;
```

### 되돌리기

- **API 이미지 롤백(1.15.1)**: DB는 건드리지 않는다. 두 이미지 모두 `PushDailyBudget`을 쓰지 않는다. 1.16.0 대상 칸은 DB에 그대로다. memo 칸은 nullable이라 1.15.1이 무시한다([롤백의 범위](../../../apps/api/docs/deployment.md#롤백의-범위)).
- **`PushDailyBudget` 모양이 꼭 필요할 때만** 아래 SQL을 쓴다. 모양만 돌아오고 데이터는 돌아오지 않는다. 지울 때 비어 있음을 guard가 확인했으므로 잃은 행은 없다. guard를 우회해 행이 필요해진 경우에만 배포 전 RDS 스냅숏을 **새 인스턴스로** 복원해 그 행을 옮긴다. 운영 인스턴스를 스냅숏으로 덮지 않는다(그 뒤 쓴 데이터를 잃는다).

```sql
-- 20261112095904_drop_push_daily_budget 되돌리기(모양만)
CREATE TABLE "PushDailyBudget" (
	"automatedCount" integer DEFAULT 0 NOT NULL,
	"createdAt" timestamp(3) DEFAULT now() NOT NULL,
	"id" serial PRIMARY KEY,
	"lastSentAt" timestamp(3),
	"localDate" date NOT NULL,
	"updatedAt" timestamp(3) NOT NULL,
	"userId" text NOT NULL,
	CONSTRAINT "PushDailyBudget_userId_localDate_key" UNIQUE("userId","localDate")
);
ALTER TABLE "PushDailyBudget" ADD CONSTRAINT "PushDailyBudget_userId_fkey"
	FOREIGN KEY ("userId") REFERENCES "User"("id") ON DELETE CASCADE ON UPDATE CASCADE;
```

- `retire_unused_columns`는 DB를 바꾸지 않아 되돌릴 것이 없다.
- memo 칸까지 되돌려야 할 때만: 1.15.1 이미지로 돌린 뒤 아래 SQL을 실행한다. 1.15.2 이미지가 도는 동안에는 실행하지 않는다.

```sql
-- 20261111173409_memo_idempotency_key 되돌리기(검토 후, 1.15.1 이미지에서만)
DROP INDEX IF EXISTS "Memo_userId_idempotencyKey_key";
ALTER TABLE "Memo" DROP COLUMN IF EXISTS "requestHash";
ALTER TABLE "Memo" DROP COLUMN IF EXISTS "idempotencyKey";
```

- `drizzle.__drizzle_migrations` 기록은 지우지 않는다. 지우면 다음 migrate가 그 마이그레이션을 다시 돌린다.

## 배포 순서

순서는 서버 배포 → 안정화 확인 → 앱 제출이다(expand → contract). 이번 contract(`PushDailyBudget` 삭제)는 1.15.1·1.15.2 어느 쪽도 쓰지 않는 것만이라, migrate가 API 교체 앞에 돌아도 된다. 1.15.1이 아직 쓰는 칸은 1.16.0으로 미뤘다. 앱이 나간 뒤에는 서버를 1.15.2 이전으로 되돌리지 않고 수정 배포로 대응한다([서버 배포](../../../apps/api/docs/deployment.md#롤백의-범위), [앱 배포 순서](../../../apps/mobile/docs/build-and-release.md#배포-순서)).

1. **머지 전 운영 읽기 전용 확인**: 위 A~D·F를 돌리고 숫자를 적는다. 쓰기는 하지 않는다.
   - A가 0이 아니면 `drop_push_daily_budget` 커밋을 빼고 머지한다. 그대로 두면 배포가 migrate에서 멈춘다(데이터는 지켜진다).
   - D가 10만 행을 넘으면 memo 색인을 나눌지 먼저 정한다.
   - B·C는 1.16.0 판단 자료다. 값이 있어도 이번 배포는 그대로다.
2. **머지**: stack PR을 위에서부터 머지한다. CI는 tip(`ci:stack-tip`)에서 누적 diff로 한 번 돈다.
3. **시각**: 03:00~03:40 KST(일간 정리 작업)와 07:00~08:00 KST(아침 리마인더)를 피한다.
4. **RDS 수동 스냅숏**: 이름은 `aido-pre-1-15-2-<YYYYMMDD-HHmm>`이다. 상태가 `available`이 된 뒤 다음 단계로 간다. 스냅숏 없이 migrate를 돌리지 않는다.
5. **배포 직전 확인**: E를 돌린다. 2초 넘게 열린 트랜잭션이 있으면 끝나기를 기다린다. `deadlock_timeout`이 1s인지 본다.
6. **서버 1.15.2 배포**: migrate(세 마이그레이션, 한 트랜잭션) → API 교체 → `/health` 확인이다. 수동 배포는 Mac에서 CI와 같은 설정으로 이미지를 빌드해 GHCR에 올리고, 서버는 pull만 한다(t4g.small에서 빌드하지 않는다).
   - migrate가 실패하면 API는 바뀌지 않고 1.15.1이 그대로 돈다. 사용자 영향은 없다. migrate 로그(`deploy.sh`가 마지막 50줄을 남긴다)에서 원인을 본다.
   - `55P03`(잠금 0.5초 초과)이면 E를 다시 보고 같은 SHA로 다시 배포한다.
   - `P0001` "PushDailyBudget에 행 …"이면 다시 돌리지 않는다. A를 다시 보고 그 커밋을 뺀 SHA로 배포한다.
7. **배포 뒤 읽기 전용 확인**: 위 "배포 뒤" 쿼리 다섯 개를 돌린다.
8. **서버 확인**: 운영 응답에서 아래를 본다. 운영 기능 플래그는 바꾸지 않는다. `NUDGE_1111`·interceptor는 로컬에서 플래그를 꺼 확인한다([기기 확인](qa-matrix.md)).
   - 테스트 계정으로 인증 코드를 연달아 요청해 `VERIFY_0753`에 `details.remainingSeconds`가 실리는지.
   - `GET /v1/todos/overview`가 200인지.
   - Sentry 예외 메시지에 DB 바인딩 값·이메일이 없는지. 배포 시각 앞뒤로 `SYS_0005`·`SYS_0001` 5xx가 늘지 않았는지.
9. **API 롤백이 필요하면**: `scripts/deploy.sh --rollback`으로 1.15.1 API만 다시 만든다. DB는 그대로 둔다(위 되돌리기). 스냅숏 복원은 데이터 손상 같은 경우에만, 새 인스턴스로 한다. 앱 제출 전까지만 1.15.1로 되돌릴 수 있다.
10. **앱 빌드**: 다른 작업이 없을 때 한 플랫폼씩 차례로 한다. `eas build --local --platform ios --profile production`과 `--platform android`다. Node는 24.22.2(`eas.json`)다. 결과 `.ipa`·`.aab`는 바탕화면에 둔다. Expo 패치에 네이티브 변경이 있어 EAS Update로 내보내지 않는다.
11. **스토어**: `apps/mobile/store-metadata/1.15.2/release.json`을 만들고 listing의 `release_notes`를 [스토어 문구](store-listing.md)로 바꾼다. 이어서 `pnpm --filter @aido/mobile store:check`를 돌린다. 이 파일이 없으면 `store:check`가 실패한다.
12. **출시 뒤 이틀**: Sentry 이벤트 수를 1.15.1과 비교한다. 새 `query_cache` 보고와 SDK 코드 오류 이벤트, linked exception의 개인정보를 본다.

## 알려진 한계와 남은 일

- **iOS 친구 목록 편집 토글**: 미끄러짐·핸들·삭제 버튼 페이드는 1.15.1과 같다. 단 Menu가 있는 Link의 네이티브 감싸개 때문에 안쪽 ListRow만 다시 그려져 아바타가 200ms 다시 나타난다(expo-router `Link.Menu` 한계). Android는 1.15.1과 같다. 기기에서 1.15.1과 나란히 비교한다. <!-- da0896237 -->
