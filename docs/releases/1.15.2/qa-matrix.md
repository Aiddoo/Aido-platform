# 1.15.2 기기 확인 순서

기기는 iPhone → Duo·폴더블 → iPad·Mac → 저사양 Android 순서로 본다. 한 기기 안에서는 위험이 큰 것부터 본다(데이터 안전 → 푸시·이동·토큰 → 폼 → 화면).

**출처**

- `briefs/device-checklist.md`의 모든 항목. 출처 칸에 체크리스트 태그(`[F1]`, `[p2b]` 등)를 그대로 적는다.
- 게이트 리뷰 `r17`의 기기 확인 추가 12항목(`r17 #n`).
- 출시 노트의 의도한 화면 차이와 수정 가운데 기기에서만 보이는 것(`⊕` + 커밋).

기준 코드는 `chain-41`이다. 코드 고정 `chain-39-frozen` 뒤 기기 QA·tip CI에서 찾은 수정([32.44/32])과 탭 이동 정리([32.45/32])를 더했고, stack 맨 위 `[32.46/32]`와 코드가 같다. `chain-39-frozen`으로 이미 본 항목 가운데 두 PR이 바꾼 화면(탭 이동·푸시·링크·위젯 착지, 탭 밖 화면 위 링크, 알림함, 탭 안 목록 끝, 댓글 초안, 시트 토스트, 저장 연타, 링크로 연 카테고리 추가의 한도, 안내 말풍선 아래 칩, 비밀번호 안내·가입 확인 칸, 짧은 TTL 토큰 갱신, iPad·Duo 창 폭을 바꾼 뒤 주·월 달력)은 `chain-41`에서 다시 본다. 진행 상태는 [출시 기록의 기기 확인 상태](README.md#기기-확인-상태)에 있다. 근거 PR 번호(`[n/32]`·`[32.NN/32]`)의 제목은 [출시 기록의 PR 목록](README.md#pr-목록)에 있다.

## 진행 규칙

- 시뮬레이터는 한 번에 하나만 켠다(iPhone 18 Pro → iPhone Duo → iPad). 부팅과 설치가 끝난 뒤 앱을 한 번만 열고, 끝나면 shutdown한다. 부하와 SpringBoard 오류를 피하려는 것이다.
- API는 로그 전용으로 띄운다. 로컬 DB는 5433이다. `apps/api/.env`는 쓰지 않는다. 8080은 다른 세션이 쓰므로 쓰지 않는다.
- 짧은 access TTL은 `.env.development` 값으로만 준다. 운영에는 쓰지 않는다.
- QA AFTER(`QA/2_후`)가 끝나면 Maestro `commands.json`의 비밀번호를 가린다.
- 실패하면 기기·빌드·서버 표시·재현 순서를 적고 다음 항목으로 넘어간다.
