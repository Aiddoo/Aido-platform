# 1.11.0: 콕 찌르기 답장·감사와 오늘의 위젯

## 사용자 결과

친구가 보낸 콕 찌르기에 “시작해볼게”, “응원 고마워”, “조금 뒤에 할게”로 답장한다. 답장만으로 할 일이 완료되지는 않는다. 공개 할 일을 직접 완료한 뒤, 해당 할 일을 찔러 준 현재 친구에게 감사를 보낼 수 있다. 같은 답장과 같은 친구에게 보내는 감사는 중복 알림을 만들지 않는다.

기존 FREE 하루 3회, ACTIVE 무제한, 동일 할 일 24시간 쿨다운은 유지한다. 답장과 감사에는 새 유료 제한을 추가하지 않는다. 요청 당시의 소유자·공개 범위·현재 상호 친구 관계를 서버가 검증한다.

## 책임·네이밍 기준

Nest의 Module/Provider/Controller와 저장소의 실용형 DDD 구조를 함께 따른다. Controller는 endpoint UseCase를 직접 주입한다. 단순 전달 Facade를 추가하지 않는다. Aggregate는 한 객체의 상태 전이를 소유하고, Policy는 도메인 객체와 외부 컨텍스트로 boolean을 판단한다. 화면 색상·문구·JSX는 Policy에 넣지 않는다.

파일은 kebab-case + 역할 접미사다. `reply-to-nudge.use-case.ts`, `nudge.repository.port.ts`, `prisma-nudge.repository.ts`, `nudge-notifier.adapter.ts`, `nudge-interaction.config.port.ts`를 사용한다. 클래스는 PascalCase, 변수·DI 필드는 camelCase다. `config`, `queue`, `publisher`, `localeReader` 대신 `nudgeInteractionConfig`, `notificationQueue`, `notificationPublisher`, `notificationRecipientLocaleReader`처럼 공급자 역할을 드러낸다. boolean은 `isEnabled`, 식별자는 `nudgeId`/`todoId`, 시각은 `repliedAt`/`replyUpdatedAt`/`thankedAt`으로 구분한다.

공개 availability 응답의 `enabled`와 기존 DB/API 필드명은 이름 정리를 이유로 바꾸지 않는다. API는 탭·double quote, 모바일은 2 spaces·single quote를 기존 Oxfmt 설정으로 유지한다.

## 트랜잭션·경쟁 요청

답장·감사는 기존 CLS UnitOfWork로 묶는다. Prisma repository가 활성 transaction을 사용하며, 대상 할 일을 잠근 뒤 최신 관계·상태를 다시 확인한다. 알림과 push outbox는 같은 transaction 안에 기록한다. 알림 발송기가 transaction 밖에서 전송하고 기존 dedupe/retry를 유지한다.

감사 preview는 `throughNudgeId`를 반환한다. 감사 요청은 그 시점까지의 수신 찌르기만 대상으로 삼는다. 완료를 취소하고 다시 완료해도 같은 `(todoId, senderId)`의 감사는 partial unique index로 한 번만 기록된다. 이 집합 원자성에는 명명된 repository capability와 최소 SQL 잠금을 사용하고, 일반 읽기·관계·페이지 조회는 Prisma를 사용한다.

## 하위호환·롤아웃

- 두 migration은 nullable 열과 새 notification enum만 추가한다. 기존 열·endpoint·응답을 제거하지 않는다.
- 기존 `/notifications` 계약의 enum과 페이지는 새 reply/thanks 타입을 포함하지 않는다. 필터를 pagination 전에 적용한다.
- 새 `/notifications/inbox`는 확장 타입을 제공한다. unread-count/read-all도 `X-App-Version`으로 같은 capability를 사용하고 `Vary`를 설정한다.
- 새 push는 1.11.0 이상으로 등록된 device에만 발송한다. 이전 device의 일반 찌르기와 기존 push는 유지한다.
- `NUDGE_INTERACTIONS_ENABLED` 기본값은 false다. 새 앱은 availability를 조회하므로 서버 기능이 꺼져 있어도 기존 화면을 사용할 수 있다.
- 기존 notification 캠페인 키·우선순위·dedupe 키는 그대로다. `copyRevision: 1.11.0`은 관측용 metadata다.
- 앱 runtimeVersion은 fingerprint를 유지한다. 새 네이티브 위젯 SDK를 기존 binary에 OTA로 덮어쓰지 않는다.
- pg-boss 12.27의 schema 37을 유지한다. 12.35의 schema 43 업그레이드는 이전 서버로의 rollback을 막으므로 이번 릴리스에 포함하지 않는다.
- Prisma 7.10은 이미 사용 중인 메이저다. 필요 없는 메이저 변경을 추가하지 않는다.

## 재사용과 의존성

`es-toolkit`, `ts-pattern`을 workspace catalog에 두어 서버·클라가 같은 버전을 소비한다. 단순 boolean·직접 필드 비교까지 match로 감싸지 않는다. 실제 분기·컬렉션 조합에서만 사용한다. 기존 UoW, FollowReader, NotificationQueue/Publisher, pg-boss runtime, shared DTO/오류를 재사용한다. ORPC와 업로드를 추가하지 않는다.

`fromPrisma`는 상단 정적 import다. 런타임 초기화만 필요한 시점으로 미루며, stop 시 worker/subscription을 정리한다. Prisma transaction과 큐 adapter 경계를 유지한다.

기존 공개 OpenAPI fingerprint는 변경하지 않았다. 새로운 응답과 endpoint만 snapshot에 추가했다. 테스트 이름은 한국어, 시나리오는 Given / When / Then으로 구분한다.

### 최종 스택의 상태 소유권·호환 점검

- 서버 상태는 Query Options의 key·`queryFn`·`AbortSignal`·페이지 커서와 Mutation의 invalidation으로 관리한다. 조회 응답을 `useState`나 Context에 복사하지 않는다.
- 검색 입력 초안과 폼은 화면의 React 상태 또는 기존 react-hook-form이 소유한다. 기존 `Input`의 `value`·`onChange` 계약을 사용한다.
- 알림 category·할 일 ID·날짜·위젯 생성 action은 Expo Router의 지역 search schema로 검증한다. 선택된 category는 `router.setParams`로 변경한다.
- 인증·DI·Query Provider는 bootstrap에서 조립한다. LocalDateProvider는 로컬 날짜를, WeatherSessionProvider는 인증 영역의 날씨 세션을 소유한다.
- 위젯 초기 목적지는 인증 복원이 끝날 때까지의 일회성 대기 상태다. 실제 현재 경로·탭 상태를 복제하지 않는다. frame은 cleanup에서 취소하고 미인증 확정 시 대기 목적지를 폐기한다.
- 수신 콕 전용 목록은 알림에 통합했다. `NudgeInboxLink`, `NudgeList`, 이전 단일 감사 preview query를 제거했다. `/nudges?direction=received`는 기존 링크 호환용 Redirect만 유지한다.
- Android는 공식 `react-native-android-widget` CNG/task adapter를 platform factory에서 조립한다. Expo Widgets의 iOS renderer는 유지한다. 이전 수동 Kotlin provider·migration·refresh patch를 제거했고, 배포된 세 provider FQN·widget ID와 snapshot v1은 유지한다. owner가 없는 이전 snapshot은 첫 인증 동기화 전 안전한 stale 안내로 처리한다.

### Android 종료 상태와 실제 클릭 검증

기존 경로에서 프로세스만 종료되고 최근 앱의 ActivityRecord가 남은 상태에서 Expo Linking의 초기 URL이 이전 `/feed`인 경우를 재현했다. 공식 task는 정확한 URI와 위젯 소유자를 기존 MMKV 저장소에 일회성 command로 기록한다. background에서는 동작 없는 `/feed?date=today`로 앱만 깨우며, 인증된 현재 계정과 command의 소유자가 같을 때 entry hook이 목적지를 한 번 복원한다. 오래된 계정의 실제 URI를 native Router가 먼저 여는 경로를 제거했다.

공식 라이브러리 [이슈 #154](https://github.com/sAleksovski/react-native-android-widget/issues/154)와 같은 clock-derived PendingIntent 실패는 기존 카드 전체를 공식 `ListWidget` 단일 항목으로 감싸 해결한다. Android collection의 stable template와 항목별 fill-in을 사용한다. 소/중/대 provider FQN과 기존 widget ID를 유지하며, 수동 native/vendor patch는 적용하지 않는다. 7개 날짜·4개 할 일·생성·뒤로가기 및 10회 실제 완료 상태 갱신 후 클릭을 검증했다. template 3개는 유지되고, 첫 렌더 세대의 사용되지 않는 clock token은 제거되어 최근 두 세대만 남았다. 이 결과를 전체 메모리 누수가 없다는 증거로 확대하지 않는다.

QA Release는 별도 CNG snapshot의 debuggable manifest flag만 사용한다. `BuildConfig.DEBUG=false`, embedded bundle, production manifest와 flag 한 개만 다른 것을 확인했다. 실제 tap 직전 PID 부재·같은 ActivityRecord·launcher PID 유지 조건을 기록한다. Home 전환이 끝나기 전 입력을 보내 native click 이벤트가 없던 harness 실패는 실제 Router 실패와 구분한다. 최종 binary에서 홈 전환을 마친 실제 한 번의 터치로 큰 위젯 cold 상세·생성과 중간 상세·작은 홈을 통과했으며, 무료·유료 계정 전환과 최신 Android 37개·iOS 41개 캡처 검증을 마쳤다. 스택 CI와 최종 production 재빌드는 별도 release gate로 유지한다.

## 공식 자료와 적용 경계

- [Nest providers](https://docs.nestjs.com/providers), [modules](https://docs.nestjs.com/modules): Nest의 DI/조립 기준. Aggregate/VO 폴더는 이 저장소의 DDD 규칙이다.
- [Expo protected routes](https://docs.expo.dev/router/advanced/protected/): 인증 복원 중 접근 불가 화면은 anchor로 이동한다. 초기 위젯 URL을 검증하고 인증 영역 마운트 뒤 한 번 재적용한다.
- [Expo build properties](https://docs.expo.dev/versions/latest/sdk/build-properties/), [Android R8 full mode](https://developer.android.com/topic/performance/app-optimization/full-mode): 생성자의 reflection 사용은 명시적인 keep rule로 보호한다.
- [Expo local builds](https://docs.expo.dev/build-reference/local-builds/), [easignore](https://docs.expo.dev/build-reference/easignore/): local production 빌드도 필요한 환경을 직접 제공하고 소스·asset·plugin만 포함한다.
- [RevenueCat Test Store](https://www.revenuecat.com/docs/test-and-launch/sandbox/test-store): Test Store key는 debug 전용이다. Release에서는 플랫폼 key만 사용한다.

## 최종 문구와 시트 수명주기 개선

UI 문구는 한국어의 편안한 해요체와 자연스러운 영어로 맞춘다. 친구의 직접 답장 문구는 반말을 유지한다. 새 푸시 문구는 기존 알림 생성 카탈로그에서 조립하며, 이미 저장된 알림 본문이나 사용자가 입력한 메시지를 다시 쓰지 않는다. URL enum·알림 type·i18n base key·보간 변수는 유지한다.

| 답장 제목      | 짧게 마음을 전해보세요                                     | 친구에게 한마디 전해볼까요?                                 |

```tsx
      <NudgeDetail.ThanksStatus />
    ) : (
      <Text size="b3" shade={6}>
        {t('interaction.completedThanksHint')}
      </Text>
    )}
    <NudgeThanksButton
      todoId={nudge.todoId}
      className={status === 'THANKED' ? 'hidden' : undefined}
    />
  </VStack>
) : status === 'THANKED' ? (
  <NudgeDetail.ThanksStatus />
) : null;
```

위 코드는 상태 분기 발췌이며 실제 화면의 나머지 분기는 파일 전체 Before/After에서 확인한다. 숨긴 버튼은 시트의 소유자 역할만 유지한다. 화면을 떠날 때의 기존 Overlay cleanup은 유지한다.

### Android 시스템 뒤로가기 구독

공용 시트의 Android back subscription은 React Native가 문서화한 직접 콜백 구독 방식을 따른다. `onDismiss`가 바뀌면 이전 구독을 제거하고 현재 콜백을 등록한다. 숨김·unmount에서도 정리한다. 사용자 navigation stack을 강제로 초기화하지 않는다.

Before:

```tsx
const dismiss = useEffectEvent(onDismiss);
useEffect(() => {
  if (Platform.OS !== 'android' || !isVisible) return;
  const subscription = BackHandler.addEventListener('hardwareBackPress', () => {
    dismiss();
    return true;
  });
  return () => subscription.remove();
}, [isVisible]);
```

After:

```tsx
useEffect(() => {
  if (Platform.OS !== 'android' || !isVisible) return;
  const subscription = BackHandler.addEventListener('hardwareBackPress', () => {
    onDismiss();
    return true;
  });
  return () => subscription.remove();
}, [isVisible, onDismiss]);
```

[React Native BackHandler 문서](https://reactnative.dev/docs/backhandler)의 subscription/remove 계약을 사용한다. 최신 콜백 호출·이전 subscription 제거·숨김/unmount 정리를 검증하는 한국어 Given/When/Then 테스트 3개가 통과했다. 단독 시트 확인뿐 아니라 할 일 완료 이후의 전체 플로우에서 실제 Android back으로 시트만 닫히는 것을 확인했다.

추가 문구 검증: 서버 알림 카탈로그 5 files / 53 tests, 모바일 i18n·카탈로그·양 OS 위젯 4 suites / 97 tests 통과. 문구 변경 후 native Release를 다시 빌드하여 캡처를 갱신한다. QA 빌드는 개발 API를 사용하는 검증용이며 스토어 제출용 production AAB/IPA가 아니다.

### 문구 변경 후 Android Release 캐시 검증

카탈로그 변경 후 이전 번역이 남은 APK를 발견했다. Expo CLI의 `--no-build-cache`만으로는 기존 Gradle JS bundle이 갱신되지 않는 경우를 실제 확인했다. 최종 Android native QA는 앱 데이터·로그인 상태를 유지한 채 `./gradlew :app:clean :app:assembleRelease --max-workers=2`로 앱 빌드 산출물을 다시 생성하고 `adb install -r`로 설치한 앱에서 수행한다. 파일이 빌드되었다는 로그만으로 문구 반영을 판단하지 않고 실제 UI의 새 제목·버튼을 assert한다. 앱 데이터와 기존 로그인 상태는 지우지 않는다. Expo 생성 프로젝트의 빌드 도구만 사용하며 생성된 네이티브 소스를 편집하지 않는다.

### Analytics와 최종 카탈로그 확인

- `nudge_replied`와 `nudge_thanks_sent`를 기존 `AppEventMap`에 선언하고, mutation 성공 콜백에서 공용 `useTrack()`을 사용한다. 벤더 SDK를 feature에서 직접 호출하지 않는다.
- 답장은 `reply_kind`만, 감사는 서버가 실제 처리한 `recipient_count`만 기록한다. 친구 ID·이름·할 일 제목은 기록하지 않는다. 중복 요청으로 서버가 0명을 반환하면 감사 이벤트를 중복 기록하지 않는다.
- 성공·오류·0명 처리 경계를 한국어 Given/When/Then 테스트 4개로 검증했다. 최신 모바일 전체 177개 suite, 1,479개 테스트가 통과했다.
- 서버·클라이언트 KO/EN 알림 및 감사 문구를 현재 상황에 맞게 정리했다. 기존 notification type·variant key·push payload·이전 알림 기록은 유지한다.
- 랜딩 촬영은 Docker 개발 서버의 별도 예시 계정과 9종 고양이 프로필을 사용한다. AI 리포트는 앱의 기존 샘플 화면이며 제안은 예시 데이터다. 미출시 1.11.0 화면은 랜딩에 미리보기로 표시한다.
- 작은 iOS 위젯의 영어 제목은 Expo UI `lineLimit(1)`과 `minimumScaleFactor(0.7)`로 공간에 맞춘다. Swift·Kotlin 소스를 수정하지 않는다.
- Android에서 task를 남기고 프로세스만 종료한 뒤 위젯 링크를 열면 Expo Router가 새 Intent URL을 받지 못하는 조건은 여전히 배포 차단 항목이다. 정상 실행 상태·새 task에서의 성공만으로 이 조건까지 통과했다고 판단하지 않는다.
