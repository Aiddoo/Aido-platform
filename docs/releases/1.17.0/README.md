## 무엇을, 왜

기기 캘린더에 이미 있는 일정을 할 일로 한 번에 옮기고 싶다는 필요에서 시작했다. 마이 > 설정 > 캘린더 일정 가져오기에서 기기에 동기화된 캘린더(iCloud·Google·Outlook 등)를 `expo-calendar`로 읽기만 하고(쓰기·삭제 없음) 고른 일정을 할 일로 만든다. 한 번 가져오는 기능이고 동기화가 아니다.

흐름은 다음과 같다.

1. 안내 화면이 무엇을 읽고 보내는지 알리고 버튼은 `계속` 하나다. 이 버튼을 누른 뒤에만 시스템 권한 창이 뜬다.
2. 캘린더와 기간(시작일·종료일, 바로 고르기 1주·1개월·3개월·6개월·1년)을 고른다. 공휴일·생일·구독 캘린더는 처음에 선택하지 않는다.
3. 넣을 곳을 고른다: 가져올 일정을 출처 계정마다 한 줄(서비스 이름 글자 배지·캘린더 이름·개수)로 보이고, 기본은 새 할 일의 기본 카테고리 한 곳이라 새 카테고리를 만들지 않는다. 넣을 곳 카드를 눌러 다른 카테고리를 고르거나 새로 만들고(이름·색은 같은 시트 안에서), 캘린더가 2개 이상이면 `캘린더마다 다른 곳에 넣을래요`로 나눠 넣는다. 남은 자리는 고른 넣을 곳만 서버 한도(`GET /v1/todos/resource-limit`, 끝내지 않은 할 일과 진행 중 반복만 센다)로 읽어 넣을 곳 카드에 `N개 더 넣을 수 있어요`로 보이고, 이번에 넣을 일정(다른 캘린더가 같은 곳에 넣는 일정 포함)이 300개를 넘기면 몇 개만 들어가고 몇 개를 건너뛰는지, 이미 가득 찼으면 다른 곳을 고르라고 미리 알린다. 나눠 넣으면 건너뛰는 줄마다 경고가 붙는다. 시트의 카테고리 줄은 자리 수를 보이거나 막지 않는다. 처음 한 번은 코치마크가 넣을 곳을 짚는다.
4. 옵션: `시간도 가져오기`(처음 켬, 끄면 날짜만이고 리마인드 없음), `친구에게 공개`(처음 끔).
5. `가져오기`를 누르면 서버가 백그라운드로 처리한다. 앱을 나가도 되고 네트워크가 끊겨도 이어진다. 끝나면 가져온 수와 건너뛴 이유를 보인다.
6. 7일 안에는 되돌릴 수 있다. 끝내지 않은 가져온 할 일만 지우고 완료한 것은 남긴다. 같은 일정은 두 번 가져오지 않는다. 같은 일정은 제목·시작·끝·종일이 같은 일정이라 다른 기기·다른 캘린더에서 다시 가져와도 한 번이고, 캘린더에서 제목이나 시간을 고친 뒤 다시 가져오면 새 할 일이 하나 더 생긴다.

요금제: 가져오기는 무료이고 범위만 다르다. 무료는 오늘부터 30일 뒤까지, 프리미엄은 365일 뒤까지다. 숫자는 서버 `PLAN_CATALOG`의 `CALENDAR_IMPORT`가 주인이고 앱은 서버 값을 그린다. 카테고리 한도는 그대로다. 구독 화면·업셀에도 이 범위를 적는다.

그 밖: 1.17.0 새 기능 소개(1.15.0 소개를 대체, 1.16.0 소개는 유지), Mac에서 날씨를 열 때마다 위치를 다시 묻던 문제 수정(권한을 기기에 기억). 안쪽 변경은 새 할 일이 많을 때 리마인드를 한 번에 예약하는 것과 429 `Retry-After`를 따르는 것이다.

## 호환

[호환](../../conventions/compatibility.md) 규칙대로 출시 앱(1.16.x 이하)이 보는 계약은 추가만 한다. 출시 앱은 새 라우트를 부르지 않고 권한 응답의 새 값은 무시한다. 가져온 할 일은 출시 앱에서 평범한 할 일로 보인다. DB 마이그레이션은 `04-server-todo-imports-slice`에 있다.

## 배포 순서

1. 서버를 배포하기 바로 앞에 운영 env의 새 기능 소개 키 세 개만 바꾼다: `FEATURE_DISCOVERY_CAMPAIGN_ID=feature-discovery-1.17.0`, `FEATURE_DISCOVERY_MIN_APP_VERSION=1.17.0`, `FEATURE_DISCOVERY_LAUNCHED_AT=2026-11-24T15:00:00.000Z`(출시일 한국 0시). 새 슬롯이 이 값을 읽어 출시 때 다시 띄우지 않는다. 1.16 앱은 최소 버전에 걸려 자동으로 열지 않는다. 바꾸는 방법은 [서버 배포와 롤백](../../../apps/api/docs/deployment.md)의 운영 env 규칙(키 이름·해시로만 비교)을 따른다.
2. 서버 stack(01~05)을 함께 머지하고 서버를 배포한다(Blue-Green, [서버 배포와 롤백](../../../apps/api/docs/deployment.md)).
3. `/health`, pg-boss 큐 처리, 로그 error를 확인한다.
4. 시뮬레이터 QA를 iPhone → iPad → 접은 Duo 순서로 한다. 캘린더에 일정을 미리 넣어 둔다. 결과는 [qa-matrix](qa-matrix.md)에 확인한 값만 적는다.
5. 스토어에 제출한다. `expo-calendar`가 네이티브 모듈이라 fingerprint가 바뀌어 OTA로 낼 수 없고 스토어 빌드가 필요하다. 문구는 `store:check`로 확인한다.
6. 스토어에서 받을 수 있게 된 뒤 플랫폼마다 `AppRelease`를 1.17.0으로 올린다([새 기능 소개 출시](../../../apps/mobile/docs/whats-new-release.md)).

## 확인하지 못한 것

- 서버 stack 머지·운영 배포, 시뮬레이터·실기기 QA, 서명된 빌드의 Info.plist·AndroidManifest 권한 값, 콘솔 신고(App Privacy·Data safety) 입력: 모두 미확인.
- 앱은 2026-11-25에 낸다. 개인정보 처리방침·이용약관의 캘린더 일정 가져오기 조항은 11-24에 게시하고 시행일을 11-25로 당겼다(사용자 결정). 이용약관 제3조의 7일 전 공지와 어긋나는 점은 사용자가 알고 정했다.
