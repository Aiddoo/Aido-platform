# 1.17.0 개인정보 라벨 메모

**상태: 제안, 콘솔 입력 전.** 코드의 실제 전송 경로와 대조한 제안이고 콘솔의 현재 값은 이 저장소에서 확인할 수 없다. 최종 신고 판단과 제출은 사용자가 한다. 개인정보 처리방침 문구는 aido.kr에 게시되어 있고 시행일은 출시일인 2026-11-25다.

## 바뀌는 데이터 흐름

- 사용자가 `가져오기`를 누르면 고른 일정의 제목·날짜·시간을 아이두 서버로 보내 할 일을 만든다.
- 캘린더 id·일정 id는 기기에서 sha256으로 해시해 보낸다(같은 일정을 두 번 가져오지 않는 데 쓴다).
- 참석자·메모·장소는 읽지도 보내지도 않는다. 일정 제목은 할 일 생성에만 쓰고 로그·Sentry·분석에 넣지 않는다(계획 기준, 구현 대조는 QA에서).
- 캘린더에는 쓰거나 지우지 않는다. 읽기 전용이다.

## App Store Connect (App Privacy)

| 항목                              | 제안 값                                                  | 근거                                                    |
| --------------------------------- | -------------------------------------------------------- | ------------------------------------------------------- |
| User Content > Other User Content | 수집함, 사용자와 연결됨, 추적에 쓰지 않음, 목적: 앱 기능 | 고른 일정의 제목·날짜·시간이 서버에서 할 일로 저장된다. |

그 밖 항목은 1.16.1과 같다. 새 데이터 종류는 없다. "추적"은 아니요다.

2026-11-24 App Store Connect에서 확인했다: "기타 사용자 콘텐츠(앱 기능, 사용자와 연결됨)"가 할 일 내용으로 이미 게시돼 있어 바꿀 것이 없고, 다시 게시하지 않았다. Apple에는 캘린더라는 데이터 종류가 따로 없다.

## Google Play (Data safety)

| 항목                       | 제안 값                                                                                                   | 메모                                                                     |
| -------------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Calendar > Calendar events | 수집함, 공유 안 함, 선택 사항(Optional), 목적: 앱 기능(App functionality), 전송 중 암호화, 삭제 요청 가능 | 가져오기는 사용자가 시작할 때만 일어난다. 할 일은 계정 삭제 때 지워진다. |

2026-11-24 Play Console에 위 값으로 "캘린더 일정"을 넣고 **임시저장만** 했다(수집함·공유 안 함·임시 처리 아님·사용자 선택·앱 기능). 지금 판매 중인 앱은 캘린더를 읽지 않으므로 1.17.0 빌드를 올릴 때 데이터 보안 양식을 저장(제출)한다.

## 권한

- iOS: `NSCalendarsFullAccessUsageDescription`(iOS 17+에서 일정을 읽으려면 full access가 필요하고 write-only로는 읽을 수 없다)와 `NSCalendarsUsageDescription`. 미리 알림 권한 키는 넣지 않는다(`remindersPermission: false`). 문구 원본은 `apps/mobile/native-locales/{ko,en}.json`이다.
- Android: `READ_CALENDAR`만 쓴다. `WRITE_CALENDAR`는 `blockedPermissions`로 뺀다(`app.config.ts`). 계획 기준으로 `READ_CALENDAR`는 Play의 restricted 권한이 아니다.
- 빌드된 Info.plist·manifest의 최종 값은 확인하지 않았다(미확인). 서명된 빌드로 [qa-matrix](qa-matrix.md) J1·J2를 확인한다.

## 사용자 확인 항목

1. 위 제안을 콘솔에 입력하고 현재 값과 대조한다.
2. Play Data safety에서 서버 처리를 "공유"로 보지 않는 해석이 맞는지 확인한다(서비스 제공자 정의, 1.15.0 항목과 같은 판단).
3. 처리방침 시행일(2026-11-25)과 같은 날 낸다.
