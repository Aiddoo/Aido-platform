# 1.14.2: 푸시 도달률·기기 상태·레거시 정리

기준: `stack:1.14.2`(PR #1209 포함, base `main` `55e1ce0d2`). 클라이언트는 [1.14.2 클라이언트](../../apps/mobile/docs/releases/1.14.2-client.md), 화면 QA는 [1.14.2 QA](../../apps/mobile/docs/releases/1.14.2-qa/README.md), 서버 변경 목록은 [CHANGELOG](../../apps/api/CHANGELOG.md).

## 배경

1.14.1 업데이트 공지는 387명 중 47명에게만 갔다(건너뜀 337명 `NO_ACTIVE_TOKEN`, 3명 `PUSH_DISABLED`, 운영 DB 읽기 전용 조회). 원인은 네 가지였다.

- 권한을 한 번 거절하면 다시 묻지도, 설정으로 안내하지도 않았다. iOS 임시 허용도 거절로 봤다.
- Android 13+에서 알림 채널보다 권한 요청이 먼저라 권한 창이 뜨지 않을 수 있었다.
- 토큰은 로그인 때 한 번만 등록했다. 앱 복귀·토큰 변경 때 다시 맞추지 않았다.
- 서버는 기기 권한을 몰랐고 모든 토큰의 플랫폼을 `IOS`로 저장했다.

## 요약

- `PUT /v1/notifications/push-devices/{deviceId}`: 앱이 기기마다 권한(`status`·`canAskAgain`)과 토큰(없으면 `null`)을 보고한다. 서버는 `PushDevice`에 저장하고, 발송 가능할 때만 토큰을 활성으로 둔다.
- 기기·토큰을 로그인 세션에 묶는다. 로그아웃·전체 로그아웃·비밀번호 변경·토큰 재사용 감지·탈퇴는 그 세션의 기기와 토큰을 바로 지우고, 만료 세션은 FK CASCADE로 지운다.
- 건너뜀 사유를 `PUSH_PERMISSION_DENIED`·`PUSH_PERMISSION_NOT_REQUESTED`·`NO_ACTIVE_TOKEN`으로 나누고, v2 캠페인 조회에 `skippedByReason`(선택 필드)을 더한다.
- 앱 요청 헤더를 요청마다 한 번 `RequestClient`로 해석하고 `X-Request-Id`를 응답·로그·Sentry에 남긴다.
- 로그 오류 필드를 `errorType`·`errorCode`로 맞추고, OAuth 공급자 원문 응답과 사용자 식별자를 로그에서 뺀다.
- 1.14.1에서 예고한 레거시(댓글 이전 경로 열, 리텐션 outbox, Redis/BullMQ 작업 runtime)를 지운다.
- 앱: 알림 권한 안내 Dialog·홈 카드·설정 상태 행, 기기 상태 동기화, nitro 0.37.2(iOS 16.4~17 실행 직후 종료 수정).

## 호환

- 1.14.1 이하 앱은 `POST /v1/notifications/token`을 그대로 쓴다. 서버가 같은 use case로 처리하고(권한 `GRANTED`), 플랫폼은 deviceId 접두어 → `X-Device-Type` 헤더 순으로 정한다. 출시 앱 OpenAPI fingerprint 테스트가 통과한다.
- 새 응답 필드는 모두 선택 필드다. REST 경로·오류 코드는 지우지 않았다(`NOTIFICATION_1006`만 추가).
- 세션 없이 등록된 구 토큰은 세션 해제 대상이 아니다. 기존처럼 로그아웃 요청(`DELETE token`)과 발송 실패 처리로 정리된다.

## 배포 전 확인

- 운영 env `APP_VERSION_CHECK_{IOS,ANDROID}_LATEST_VERSION`은 스토어 최신 1.14.1로 바꿔 두었다(2026-11-04, 백업 `env-backups/.env.docker.prod.20261104T093451Z-app-version-1.14.1`). 1.14.2 심사가 끝나 스토어에 공개되면 1.14.2로 올린다.
- 이전 Redis 큐는 1.14.1 배포 때 대기 0건이었고, 이 릴리스부터 서버는 pg-boss만 쓴다.
