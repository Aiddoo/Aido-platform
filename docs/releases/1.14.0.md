# 1.14.0: 날씨 v2(WeatherKit)와 서버 정비

기준: `develop...chore/release-1.14.0` 스택(`stack:1.14.0`). 코드·문서에서 확인한 내용만 적었다. 운영 배포·실기기 검증 결과는 이 문서에 없다. 클라이언트는 [1.14.0 클라이언트](../../apps/mobile/docs/releases/1.14.0-client.md).

## 요약

- 날씨를 Apple WeatherKit 기반 `/v2/weather`로 새로 제공한다. 전 세계 위치를 저장하고, 앱 화면과 날씨 푸시가 같은 v2 리포트를 쓴다.
- `/v1` 경로와 응답은 그대로 두고 날씨 v1에 Deprecated를 표기한다.
- 푸시 문구를 해요체로 통일하고 캠페인 키·카피 리비전을 올렸다. 푸시 토큰은 소유자가 바뀌어도 충돌 없이 이전한다.
- REST 버전을 Nest URI 버저닝으로 옮기고, AI 모델을 provider registry로 풀었다. Drizzle migrate 경로와 Changesets를 정리했다.
- 결제(RevenueCat)·친구 초대 보상·관리자 권한을 프리미엄 권한 모델 하나(`PREMIUM_FEATURES`, FREE/PREMIUM/ADMIN)로 판단한다. 결제 유예·환불·TRANSFER와 보상 기간을 같은 규칙으로 처리한다.
- 가입·결제 Discord 알림에 기기·OS·앱 버전·빌드를 담고, 작업 큐 종료·외부 호출 시간 제한·WeatherKit 장애 처리를 정리했다.

## 날씨 503(WEATHER_1901) 수정

- v1 예보가 기상청이 주지 않는 발표 시각(오늘 새벽의 미래 발표, 3일 지난 발표)을 요청해 503이 나던 문제를 고쳤다. 저녁 날씨 알림도 같은 미래 발표를 요청하고 있었다.
- Sentry 추적 헤더(`sentry-trace`·`baggage`)를 우리 서비스(`api.aido.kr`)에만 붙이도록 제한했다. 이전에는 모든 아웃바운드 요청에 붙어 data.go.kr 게이트웨이가 400으로 거부했고, 날씨 조회가 전량 503이 됐다고 코드 주석에 적혀 있다 (`sentry-options.ts`).
- 격자 없는 해외 위치가 v1 KMA 경로로 오면 `WEATHER_1902`(위치 없음)로 처리한다.

## WeatherKit 호출 예산

코드 기준 캐시 규칙이다 ([keyspace](../../apps/api/src/modules/weather/infrastructure/cache/forecast/weather-report.keyspace.ts), [freshness](../../apps/api/src/modules/weather/application/models/forecast/weather-report-freshness.ts), [circuit](../../apps/api/src/modules/weather/infrastructure/adapters/forecast/weather-outbound.policies.ts)).

| 대상                   | 규칙                                                                                                      |
| ---------------------- | --------------------------------------------------------------------------------------------------------- |
| 리포트 캐시 단위       | geohash5 격자 칸 + scope(언어는 공유, 특보가 있는 칸만 언어별)                                            |
| 리포트 TTL             | 평소 30분, 2시간 안에 강수가 있으면 10분                                                                  |
| latest 스냅샷          | 6시간. 공급자 실패 시 대체로 사용                                                                         |
| 공급자 실패 캐시       | 칸별 1분                                                                                                  |
| 공급자 전체 장애 차단  | 칸과 무관하게 시간 초과·네트워크·5xx 3회 연속(30초 안)이면 1분 동안 리포트 호출 중지. 400·404는 세지 않음 |
| 가용성(availability)   | 칸별 7일, 조회 실패 시 1분 동안 재호출 중지                                                               |
| 출처 표기(attribution) | 언어별 7일, 조회 실패 시 1분 동안 재호출 중지(로고 없이 진행)                                             |
| 대기질                 | 1시간                                                                                                     |

같은 칸·scope 요청은 `CacheService.wrap` single-flight로 합쳐진다. 날씨 푸시도 같은 캐시를 읽어(`WeatherReportReader`) 알림 사용자 수에 비례해 WeatherKit을 호출하지 않는다(프로세스별 single-flight). 실제 호출량 측정값은 없다.

## 호환성

구 앱(1.13.1 이하):

- `/v1/weather` 경로와 응답은 유지한다. v1 컨트롤러 세 엔드포인트에 `deprecated: true`와 "1.13.1 이하 앱 전용, 1.14.0부터 `/v2/weather`" 안내를 넣었다.
- 푸시 payload: 날씨 알림 type(`WEATHER_MORNING`, `WEATHER_EVENING`)과 기존 필드는 유지한다. 옮기기 `DEEP_LINK` url은 1.13.x 이하 앱이 무시하고 `/weather`를 연다.
- 새 필드는 선택 항목이며 기존 DTO를 바꾸지 않는다. 배포된 v1 OpenAPI를 비교하는 e2e fixture(`released-v1*-openapi-contract.ts`)가 있으나 이 문서 작성 중 실행하지 않았다.

## 운영

- 새 env `WEATHERKIT_TEAM_ID`, `WEATHERKIT_KEY_ID`, `WEATHERKIT_SERVICE_ID`, `WEATHERKIT_PRIVATE_KEY`: 모두 있거나 모두 없어야 하고 운영에서는 필수다. `SERVICE_ID`는 앱 번들 ID가 아닌 Services ID이고, 키는 `\n`을 넣은 한 줄 PEM이다. 상세는 [설정](../../apps/api/docs/configuration.md).
- `CACHE_MAX_ITEMS=3000`을 env 예시에 명시했다(메모리 캐시 항목 한도).
- 마이그레이션 `apps/api/drizzle/20261102101848_user_location_timezone`: `UserLocation.timezone varchar(50)` 추가, `gridX`·`gridY`의 NOT NULL 해제.
- Drizzle migrate: Prisma DB를 baseline으로 넘겨받던 `init` 경로(`tooling/database-migrate/migrate.mjs`)를 지웠다. 운영 DB는 1.13.1 배포 때 baseline 기록이 생겼다는 전제이며, Drizzle 기록이 없는 오래된 DB는 지원하지 않는다.
- 버전: 앱·서버(`@aido/server`)·공유 계약(`@aido/api`)을 모두 1.14.0으로 맞췄다. 앞으로 앱 버전 하나가 릴리스 버전이고, `pnpm version-packages`가 Changesets 변경 파일을 CHANGELOG로 소비한 뒤 서버·계약 버전을 앱 버전으로 맞춘다([git 규칙](../conventions/git.md#버전)).
- 당시 배포 문서는 1.14.0 운영 env를 서버의 `~/apps/env-staging/1.14.0/apply.sh`로 단계 반영한다고 적는다. 서버 상태는 확인하지 않았다.
- 마이그레이션 `20261102163121_subscription_environment`, `20261102170201_billing_grace_and_grant_duration_ms`: 구독 환경·결제 유예·보상 기간(ms) 컬럼 추가(additive).
- 새 env `REVENUECAT_PROJECT_ID`(공개 값): Discord 결제 알림의 RevenueCat 고객 링크에 쓴다. 운영 env는 `apply.sh` pre-deploy로 반영했다.
- CHANGELOG: `apps/api/CHANGELOG.md`, `packages/api/CHANGELOG.md`의 1.14.0 항목.
- 문서: [billing](../../apps/api/docs/billing.md), [admin-notifications](../../apps/api/docs/admin-notifications.md), `apps/api/docs/push-notifications.md`(날씨 알림 v2·해요체·캠페인 규칙)와 당시 서버 구조 문서를 갱신했다.

## 운영 메모 / 남은 과제

아래 RevenueCat·RTDN 항목은 요청자가 전달한 내용이며 코드·저장소 문서로는 확인하지 못했다.

| 항목              | 상태                                                                                                                                                                    |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| RevenueCat 오퍼링 | default offering에 패키지가 없던 문제를 2026-11-03 `$rc_monthly`·`$rc_annual`(App Store, Play Store, Test Store)로 복구                                                 |
| Google RTDN       | GCP 프로젝트 `aido-484421`의 Pub/Sub로 연결 진행 중. 완료 여부 미확인                                                                                                   |
| RevenueCat 웹훅   | `environment`를 저장하고 Discord 알림에 샌드박스를 구분해 표시한다. 심사 결제가 샌드박스라 샌드박스도 권한을 준다                                                       |
| `CACHE_MAX_ITEMS` | 3000을 모든 키가 FIFO로 나눠 쓴다. 활성 칸이 약 600–700개면 칸별 리포트·latest·가용성 키로 한도가 차므로 칸 수를 지켜보고, 넘으면 한도 상향 또는 Redis 캐시 어댑터 전환 |
| °F 푸시           | 푸시 문구의 기온은 °C 고정이라 앱의 °F 설정이 반영되지 않는다. 후속 과제                                                                                                |
| WeatherKit 호출량 | 운영 호출량·캐시 적중률 측정값 없음. 배포 후 확인 필요                                                                                                                  |
| 소셜 가입 계측    | 인증 응답에 신규 가입 여부가 없어 앱이 소셜 가입을 `auth_signup`으로 구분하지 못한다. `isNewUser` 선택 필드 추가가 후속 과제                                            |
