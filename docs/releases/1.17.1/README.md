## 사용자에게 보이는 수정

새 기능·새 권한·결제 변경은 없다. 항목은 [release.json](../../../apps/mobile/store-metadata/1.17.1/release.json)과 같은 순서다.

- 버튼을 빠르게 두 번 누르거나 저장한 뒤 화면이 바뀌는 사이 다시 눌러도 요청이 한 번만 간다(로그인·비밀번호 바꾸기·재설정·친구 요청·초대 코드 확인·가져오기 시작).
- 화면 문구의 마침표·용어·같은 동작의 이름을 톤 규칙에 맞추고, 제목과 같은 말을 두 번 하는 안내를 줄였다.
- 알림의 '완료하기'를 오프라인에서 누르면 멈췄다가 연결된 뒤 실행되던 문제를 고쳤다. 이제 바로 실패 안내를 띄운다.
- 기기가 시간대를 읽지 못하면 앱이 `UTC`를 지어내 보내지 않는다. 서버도 `UTC` 보고를 보고하지 않은 것으로 읽는다.
- 24시간 표기를 고른 사용자의 알림 글 시각이 오전·오후로 나오던 문제를 고쳤다.
- 말로 메모에서 다른 메모의 녹음이 섞이거나 실패 뒤 '이어서 말하기'가 되지 않던 문제를 고쳤다.
- 저장을 기다리는 사이 화면을 벗어나면 다른 화면이 닫히던 문제를 고쳤다.
- 이름 수정·친구 추가·문의 화면을 링크로 바로 열어도 저장 뒤 대체 경로로 이동한다.

### 기기 QA에서 찾아 고친 것

다섯 다 1.17.0에도 있던 문제다. Android 수정 셋은 Google Play 문구에 두 줄(날씨 화면에서 앱이 꺼지던 문제, 일부 화면 표시 문제)로 넣었고 App Store 문구에는 넣지 않았다. 말풍선 겹침은 두 플랫폼이 같은 코드라 App Store 문구에 한 줄로 넣었고, Google Play는 500자 한도라 "일부 화면 표시 문제" 줄이 함께 가리킨다.

- 좁은 화면(iPhone·접은 Duo)의 메모 카드가 iOS 접근성 트리에 실리지 않던 것을 고쳤다.
- Android 카테고리 관리에서 둘째 줄부터 수정·삭제 버튼이 줄 밖에 그려지던 것을 고쳤다.
- 애니메이션을 끈 Android 기기에서 날씨 화면의 지역·기온이 보이지 않던 것을 고쳤다.
- Android에서 날씨 화면을 열면 앱이 죽는 일이 있던 것을 고쳤다(에뮬레이터에서 재현·확인, [qa-matrix](qa-matrix.md#날씨-화면-충돌)).
- 첫 할 일을 완료하면 뜨는 마케팅 알림 동의 시트 위에 안내 말풍선이 겹쳐 글자를 가리던 것을 고쳤다. 시트·다이얼로그가 화면을 덮는 동안 말풍선을 닫아 두고, 걷히면 자리를 다시 재서 연다(Android 에뮬레이터에서 고치기 전 1번 재현, 고친 뒤 3번 모두 겹치지 않음).

## 엔지니어링 변경

- **앱 구조**: 모델을 엔티티마다 나누고 규칙을 `XxxPolicy.method(model)`로 모았다. 폼은 화면이 갖고, 화면은 단계·경계·문구를 조립한다. 캘린더 가져오기·할 일·날씨·음성·메모·친구·알림 화면이 대상이다. 화면 구조를 옮기기 전에 그 화면의 흐름 테스트를 먼저 붙였다.
- **한 가지 방법**: 쿼리 키·캐시·영속, OS 권한, 날짜·시간대, 단계 이동·route 값 쓰기, 오류 경계·fallback, 분석 이벤트 타입을 공용 방법 하나로 맞췄다. 라이브러리가 주는 기능을 다시 만든 곳을 걷어냈다.
- **서버**: 중첩 삼항 15곳을 동작 그대로 풀고 루트 Oxlint로 막았다. 시간대 해석을 한 함수로 모으고 `"Asia/Seoul"` 리터럴을 뜻별 상수로 나눴다.
- **`@aido/api`**: 계약에 흩어진 한도 숫자를 vocabulary 상수로 모았다. 값은 그대로다.
- **테스트**: 지킬 규칙이 없는 테스트를 걷고 공용 도구·fixture로 모았다. Maestro 흐름 이름·선택자를 한 규칙으로 맞췄다.
- **도구·문서**: 패치·마이너 의존성을 올렸다. NestJS와 AI SDK 올리기는 되돌렸다. 앱 쪽 릴리스 기록을 `docs/releases/<버전>/`으로 모았다.
- **버전**: 앱 1.17.1.

## 서버 변경과 호환

[호환](../../conventions/compatibility.md) 규칙대로 HTTP 응답 모양은 더하지도 바꾸지도 않는다. 이 stack에는 `apps/api/drizzle` 변경이 없어 DB migration은 없다. Drizzle 스키마 diff는 칸 길이를 vocabulary 상수로 바꾼 것뿐이고 값은 그대로다.

| 변경                                                                  | 출시 앱(1.17.0 이하)                 | 1.17.1 앱             |
| --------------------------------------------------------------------- | ------------------------------------ | --------------------- |
| `X-Timezone`이 `UTC` 계열이면 보고하지 않은 것으로 읽고 저장값을 쓴다 | 못 읽을 때 지어낸 `UTC`가 무시된다   | 지어내 보내지 않는다  |
| 알림 글의 시각이 사용자의 12·24시간 설정을 따른다                     | 달라진 글을 받는다(요청 모양은 같다) | 같다                  |
| `@aido/api/vocabulary`에 상수 추가(한도·시간대·음성 인식 언어·오류)   | 쓰지 않는다                          | 서버와 같은 값을 읽는 |

`UTC`와 같은 이름 목록(`UTC_EQUIVALENT_TIMEZONE_NAMES`)을 앱이 읽는다. 서버 spec이 이 목록과 서버 판정이 같은지 고정한다. 저장값이 `UTC`인 계정은 리마인더·날씨·AI 제안·리포트 창이 서비스 기본 시간대로 계산된다.

## 배포 순서

1. 서버를 먼저 배포한다(Blue-Green, [서버 배포와 롤백](../../../apps/api/docs/deployment.md)). 피할 시각은 매일 03:00~04:30·07:00~08:00 KST(운영 문서), 월요일 06:00~09:00·11:30~20:30 KST, 매월 1일의 같은 두 창이다. 저장값이 `UTC`인 계정의 AI 리포트 생성 창·주간 성취·월간 리포트 푸시 시각이 서울 기준으로 옮겨져, 그 사이에 배포하면 그 주기 한 번이 빠진다(#1885 본문). 같은 계정은 배포 당일 알림이 한 번 빠지거나 한 번 더 올 수 있다(발송 시각과 날짜 키가 UTC에서 서울로 바뀐다). 배포 뒤 `/health`, 로그 error, pg-boss 큐 처리를 확인한다.
2. 앱은 1.17.1 스토어 빌드로 낸다(버전이 바뀐다). 운영 1.17.0에 JS만 먼저 EAS Update로 낼지는 fingerprint를 비교한 뒤 정한다.
3. 앱은 시뮬레이터 QA(iPhone → iPad → 접은 Duo, Android) 뒤 스토어에 제출한다. 결과는 [qa-matrix](qa-matrix.md)에 채운다.
4. 스토어 문구는 `release.json`과 listing `release_notes.txt`를 같은 순서로 맞추고 `pnpm --filter @aido/mobile store:check`로 확인한다.
5. 스토어에서 받을 수 있게 된 뒤 플랫폼마다 `AppRelease`를 1.17.1로 올린다([서버 배포](../../../apps/api/docs/deployment.md#공개-버전과-env-반영)).
