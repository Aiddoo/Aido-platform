# 1.14.2 클라이언트: 알림 권한 안내·기기 상태 동기화

기준: `stack:1.14.2` tip. 서버는 `PUT /v1/notifications/push-devices/{deviceId}`를 쓴다. 전체 릴리스는 [1.14.2](../../../../docs/releases/1.14.2.md), 화면 QA는 [1.14.2-qa](1.14.2-qa/README.md).

## 요약

- 권한 상태를 `PushPermission` 모델로 받고, 다음 행동을 `PushPermissionPolicy.nextStep`(묻기·시스템 창·설정 열기·앱 설정 켜기·없음) 하나로 정한다.
- 시스템 창 전에 앱 안 안내 Dialog를 띄운다. '나중에'면 시스템 창을 쓰지 않아 iOS의 한 번뿐인 기회를 아낀다.
- 홈 안내 카드와 알림 설정 맨 위 상태 행이 같은 정책으로 상태별 문구·버튼을 보여 준다. 닫으면 계정별로 14일 숨긴다.
- 로그인 콜드 스타트·앱 복귀·토큰 변경·언어 변경 때 기기 상태를 서버에 보고한다. 직전에 보낸 값과 같으면 보내지 않는다.
- Android 알림 채널을 권한 요청 전에 만든다. 토큰 발급은 15초 제한을 두어 APNs가 응답하지 않아도 보고·로그아웃이 멈추지 않는다.
- 요청마다 `X-Request-Id`를 보내고, 토큰 갱신 요청에도 앱·기기 헤더를 싣는다.
- nitro 0.37.2로 올려 iOS 16.4~17에서 실행 직후 꺼지는 문제를 고친다(패치 파일 없음).

## 사용자 동작 Before / After

| 상황                   | Before (1.14.1)                | After (1.14.2)                                                      |
| ---------------------- | ------------------------------ | ------------------------------------------------------------------- |
| 처음 실행              | 활성화 조건에서 바로 시스템 창 | 가치 순간에 앱 안 Dialog → 동의하면 시스템 창                       |
| 거절한 사용자          | 안내 없음, 다시 묻지 않음      | 홈 "알림이 꺼져 있어요 · 설정 열기", 설정 상태 행 "꺼짐"            |
| iOS 설정에서 다시 켬   | 다음 로그인까지 토큰 없음      | 앱 복귀 즉시 토큰 등록, 상태 행 "허용됨"                            |
| 기기 허용·앱 푸시 꺼짐 | 마케팅 배너가 함께 보임        | "푸시 알림이 꺼져 있어요 · 켜기"만 보이고 마케팅 배너는 숨김        |
| iOS 임시 허용          | 거절로 취급                    | 발송 가능으로 취급                                                  |
| 토큰이 바뀜(재설치 등) | 다음 로그인까지 옛 토큰        | 토큰 리스너로 바로 보고                                             |
| 로그아웃               | 토큰 해제 요청만               | 진행 중인 보고를 기다린 뒤 해제, 서버도 세션 폐기 때 기기·토큰 삭제 |

## 구조 변경

- 추가: `core/ports/push-notification-gateway.ts`, `shared/infra/notification/expo-push-notification.gateway.ts`, `features/notification/domains/push-permission.model.ts`, `apis/push-device.service.ts`, `hooks/use-push-device-sync.ts`, `components/push-permission-{card,dialog,status-row}.tsx`, `features/activation/hooks/use-push-permission-ask-moment.ts`.
- `NotificationService`는 받은 알림·읽음·배지·마케팅 수신 거부만 맡는다.
- 제거: `use-register-push-token-mutation-options.ts`, `usePushLocaleSync`, `shared/preferences/marketing-push-prompt.preference.ts`(피처 repository로 이동).
- 테스트는 `jest.mock('expo-notifications')` 대신 게이트웨이 stub·메모리 저장소를 DI로 넣는다.

## 분석 이벤트

`push_permission_prompt_shown`·`push_permission_prompt_dismissed`·`push_permission_requested { source, status }`·`push_permission_settings_opened { source }`. `source`는 `activation`·`feed_card`·`settings`.

## 호환

- 서버 1.14.1 이하에는 새 엔드포인트가 없으므로 앱과 서버는 함께 배포한다(서버 먼저).
- 마케팅 안내 MMKV 키(`aido_marketing_push_prompt`)는 그대로다. 저장 위치만 피처 repository로 옮겼다.
