# 1.10.0 클라이언트 아키텍처 변경

2026-10-02 최종 검증 기준. Expo Router + TanStack Query + Ky의 기존 책임 경계를 유지한다. 최종 설치한 Expo 58.0.1과 React Native 0.88.0-rc.3에 맞춰 native 입력/ref/event 타입을 적용한다. 의존성 및 네이티브 변경은 [루트 릴리스 문서](../../../../docs/releases/1.10.0.md)와 위젯 가이드를 함께 확인한다.

## 타입과 서버 상태

```ts
export function getTodoDetailsQueryOptions(service: TodoService, { todoId }: { todoId: number }) {
  return queryOptions({
    queryKey: TODO_QUERY_KEYS.details(todoId),
    queryFn: async ({ signal }) => unwrap(await service.getTodoDetails(todoId, signal)),
  });
}
```

실제 factory별 기존 cache/invalidation prefix를 유지한다. 동일 네트워크 응답을 사용하는 select는 캐시에 화면 model을 덮어쓰지 않는다. 화면 locale/time-format/category 변화는 projection에 전달한다. Expo Router의 URL은 검증된 feature hook에서 읽으며 잘못된 ID/배열/범위를 그대로 서비스에 넘기지 않는다. TanStack Start loaderDeps를 새 라우터 계층으로 도입하지 않는다.

SubTodo 정책은 전체 TodoItem을 import하지 않고 필요한 subTodoStats만 받는다. 삭제 계산만 readonly subTodos를 추가로 받으므로 Todo → SubTodo 모델 의존성이 한 방향으로 유지된다. 서버 DTO alias나 타입 단정으로 순환을 숨기지 않는다.

비즈니스 정책은 입력을 받는 순수 함수로 먼저 구현하고 Policy 객체에서 같은 함수를 공개한다. this 호출과 순환 Policy 참조를 사용하지 않는다. can/is/has/should 판정은 boolean으로 끝내고 계산 정책은 반환 값이 드러나는 이름을 사용한다. 서버가 결정하는 댓글 접근 권한/대화 topology는 공유 응답 검증 후 그대로 반영한다.

## 폼과 화면 조립

```tsx
<FormProvider {...form}>
  <FormField control={form.control} name="email">
    {({ value, onChange, onBlur }, { error }) => (
      <Input value={value} onChange={onChange} onBlur={onBlur} isInvalid={error != null} />
    )}
  </FormField>
</FormProvider>
```

부모는 값, validation, submit Promise를 소유한다. 여러 단계의 비밀번호 폼도 같은 session의 FormProvider를 유지하며 지역 field/action은 필요한 이름만 구독한다. RHF와 서버 cache에 동일 form 값을 다시 복제하지 않는다. mutateAsync의 예상 비즈니스 실패는 기존 오류 UI에서 처리하고 예상하지 못한 실패는 ErrorBoundary로 전달한다. 비동기 작업이 끝나기 전에 isSubmitting이 해제되지 않는다.

Input/Checkbox/BottomSheet 확장은 ComponentProps<typeof Original>에서 wrapper가 소유하는 필드만 Omit한다. 접근성, style, testID 등 원본 확장 지점은 유지한다. 기능이 없는 입력을 이름만 바꾸는 wrapper로 만들지 않는다. 고정 의미의 결과 섹션은 명시적 JSX를 쓰고 실제 서버 컬렉션은 map을 쓴다. 부모 화면이 outer layout을 조립하며 component 내부의 row/card 디자인 간격은 해당 component에 둔다.

## 날짜와 버전 정책

date-format.ts의 순수 함수는 locale/timeZone을 명시한다. formatter cache는 최대 32개이며 기존 dayjs 날짜 계산과 YYYY-MM-DD key를 유지한다. Intl의 h23는 자정을 00:00으로 표시하고 ko/en day-period 배치는 기존 UI와 호환된다. 날짜 기준은 LocalDateProvider의 useToday/useTodayKey를 재사용한다. 알림 debounce는 로그아웃 시 timer를 취소하고, cooldown은 한 번의 timeout과 cleanup으로 다음 tick을 예약한다. 원격 timestamp는 wire schema 검증 후 Date로 변환한다.

업데이트 확인은 마이페이지 사용자가 누를 때만 조회한다. 설치된 Application.nativeApplicationVersion을 서버 플랫폼별 최신 버전과 비교한다. 이전 버전이면 기존 store gateway를 열고, 같거나 새 버전이면 확인 dialog를 표시한다. 네트워크 실패, 잘못된 응답, disabled config, 모르는 플랫폼/버전은 기존 실패 안내를 표시하며 업데이트 강제 gate를 만들지 않는다. Expo Go/web에서 native 설치 metadata가 없으면 이 항목을 표시하지 않는다.

runtimeVersion fingerprint 정책을 유지한다. SDK/native dependency/widget/plugin 변화는 native binary와 OTA의 호환성 경계이므로 package 버전만으로 OTA 호환을 추측하지 않는다. EAS appVersionSource=remote와 autoIncrement=true는 기존 native build number 운영을 유지한다. fingerprint가 바뀐 이번 SDK 업그레이드는 새 native build를 먼저 검증한다.

## 실제 실행에서 발견한 회귀와 검증

이메일 로그인에 추가한 useErrorBoundary의 상위 context가 없어 실제 iOS에서 진입 오류가 발생했다. 최초 route 경계 수정만으로는 OverlayProvider가 별도 sibling으로 마운트한 AddTodo sheet를 포함하지 못했다. 최종 root 구성은 QueryErrorBoundary → OverlayProvider → AuthGateLayout이다. 기존 query reset·오류 reporter·fallback을 재사용하고 실제 overlay open 뒤 hook 실행·비동기 제출 오류 전달을 회귀 테스트한다.

가입 인증 뒤 `/`가 unmatched route로 남는 현상도 발견했다. 미인증 Protected 그룹 안의 index가 인증 후 제거되고, NativeTabs에는 feed/memo/mypage만 있어 `/` 화면이 없었다. index를 항상 등록하고 loading/locked → `/loading`, authenticated → `/feed`, unauthenticated → `/login`으로 exhaustive Redirect한다. SDK 58의 Protected redirectTo는 `/`를 가리킨다. root Stack은 항상 mount하고 login/signup mutation에 별도 imperative 이동을 추가하지 않는다. [Expo Protected 공식 문서](https://docs.expo.dev/router/advanced/protected/)

기존 팔레트 선언은 변경하지 않았지만 Uniwind 1.12에서 theme variant가 root scope 밖에 있어 버튼·toast 배경이 사라졌다. 기존 light/dark 선언을 :root 내부로 옮겼다. 설치된 실제 native compiler로 iOS/Android × light/dark 네 조합의 각 27개 앱 토큰을 대조했고 선언 변경 0건, unresolved 0건을 확인했다. 새 색상·브랜드 디자인을 도입하지 않았다. 근거는 `/tmp/aido-theme-token-audit.json`이다.

## native 접근성과 경고의 남은 확인

실제 iOS sheet의 AX 트리에 backdrop과 slider만 나타났다. 기존과 같은 bottom-sheet 5.2.14의 content는 accessible=true/role=adjustable이 기본이며 background/handle도 adjustable로 렌더된다. iOS는 접근성 요소인 부모 아래의 nested 요소를 숨길 수 있다. shared BottomSheet/KeyboardBottomSheet/StackedBottomSheetModal에 accessible=false를 지정해 form content 전체를 하나의 접근성 요소로 묶지 않도록 했다. 실제 iOS CategoryAdd sheet에서 TextInput과 확인 버튼의 AX 노출, 입력·저장·toast·목록 반영을 확인했다. 이 확인을 모든 sheet의 VoiceOver 검증 완료로 확대하지 않는다. [React Native 접근성 공식 문서](https://reactnative.dev/docs/accessibility)

Reanimated 4.7의 native 경고는 dependency 배열이 native에서 무시된다는 안내다. production 앱 소스의 관련 hook 호출 AST 검사에서 해당 배열 전달은 0곳이며 설치한 bottom-sheet source에서 30곳, HeroUI source에서 8곳을 확인했다. 근거는 `/tmp/aido-reanimated-dependency-audit.json`이다. vendor 경고를 전역적으로 숨기거나 앱 애니메이션을 끄지 않았다.

`ref.measureLayout must be called with a ref to a native component`는 RN 0.88 ReactNativeElement가 상대 ref를 host instance로 확인할 때 발생한다. 앱 소스에는 measureLayout 직접 호출이 없고 BottomSheetInput의 native ref 전달 구조는 기준 코드와 동일하며 타입만 새 ComponentRef 계약에 맞췄다. 실제 Hermes console stack을 Metro symbolicate해 react-native-draggable-flatlist 4.0.3의 NestableDraggableFlatList.tsx가 findNodeHandle로 얻은 숫자를 상대 ref로 넘기는 호출을 특정했다. 근거는 `/tmp/aido-measure-layout-symbolicated.json`이다. 해당 vendor는 실제 scroll host ref를 넘기는 호환 patch를 적용했으며 다음 기기 실행에서 경고 소멸을 재확인한다. host ref 확인을 우회하는 cast/polyfill이나 warning suppression은 추가하지 않는다.

## 추가 실제 기기 회귀: 설치 버전과 메모 상세 cache

실제 iOS SDK58 개발 빌드에서 executionEnvironment=bare, expoVersion의 typeof=undefined, nativeApplicationVersion=1.10.0이었다. `Constants.expoVersion !== null`은 undefined도 제외해 마이페이지 버전 설정 전체를 숨겼다. 실행 환경의 `ExecutionEnvironment.StoreClient`를 제외하고 iOS/Android 네이티브 설치 정보를 읽도록 바꿨다. package/OTA 버전을 설치 버전의 대용으로 쓰지 않으며 강제 업데이트 gate를 도입하지 않았다. [Expo58 Constants 공식 문서](https://docs.expo.dev/versions/v58.0.0/sdk/constants/)

```ts
if (
  Constants.executionEnvironment === ExecutionEnvironment.StoreClient ||
  (Platform.OS !== 'ios' && Platform.OS !== 'android')
) {
  return undefined;
}
```

Expo Go 호스트, bare 개발 빌드, standalone Android, 설치 버전 없음, web의 5개 회귀 사례가 1.010s에 통과했다(`/tmp/aido-app-version-sdk58-regression.log`). read-only Hermes에서도 새 gateway는 platform=ios/currentVersion=1.10.0을 반환했다(`/tmp/aido-app-version-hermes-evidence.log`). 개발 중 기존 DI 인스턴스는 Fast Refresh로 다시 생성되지 않았다. 전체 reload 후 실제 iOS 마이페이지에 버전 설정 행이 노출되는 것을 확인했다. 수동 확인 버튼의 실행 결과는 별도로 기록한다.

메모 수정은 실제 목록과 DB에 저장됐지만 즉시 상세를 다시 열면 예전 cache가 RHF의 defaultValues가 됐다. 수정 결과를 무시하고 invalidate만 시작한 기존 mutation을 바꿔, 서비스가 공유 응답을 검증·mapping한 MemoItem을 상세 cache에 먼저 반영한다. 먼저 시작한 상세 GET은 취소해 늦은 응답이 새 값을 덮어쓰지 못하게 하고 invalidate Promise도 mutation 완료 전에 기다린다. 고정 mutation의 동일 패턴도 함께 수정했다.

```ts
onSuccess: async (memo, { memoId }) => {
  await queryClient.cancelQueries({ queryKey: MEMO_QUERY_KEYS.detail(memoId) });
  queryClient.setQueryData(MEMO_QUERY_KEYS.detail(memoId), memo);
  trackEvent('memo_updated', { memo_id: memoId });
  queryClient.removeQueries({ queryKey: AI_QUERY_KEYS.parseMemo(memoId) });
},
onSettled: (_, __, { memoId }) =>
  Promise.all([
    queryClient.invalidateQueries({ queryKey: MEMO_QUERY_KEYS.list() }),
    queryClient.invalidateQueries({ queryKey: MEMO_QUERY_KEYS.detail(memoId) }),
  ]),
```

form을 refetch마다 reset하는 effect는 추가하지 않아 편집 중 입력을 유지한다. 실제 QueryClient와 MemoService의 응답 검증을 사용하는 두 회귀 사례가 즉시 다시 열 때의 수정 cache, 늦은 이전 GET의 덮어쓰기 방지를 확인한다. test client는 mutation gcTime=Infinity와 unmount/cancel/clear를 사용해 수동으로 만든 mutation의 GC timer가 테스트 종료를 붙잡지 않게 했다. 최초 실행은 GC timer가 남았고 수정 후 `--detectOpenHandles` 실행은 2 cases, 34.849s, 정상 종료·추가 open handle 없음이었다(`/tmp/aido-memo-cache-regression-clean.log`). transform 조건이 달라 다른 실행 시간과 비교하지 않는다.
