# 1.11.0 클라이언트: 현재 구조와 출시 검증

## 현재 release gate (2026-10-05)

이 문서는 1.10.1 기준 `33f7e1d3`와 2026-10-05의 1.11.0 작업 트리를 비교한다.
After 코드는 현재 구현을 설명하며, 아직 최종 production AAB/IPA의 source commit 검증을 뜻하지 않는다.
Android의 process-killed / retained-recents 종료 상태 이동과 재렌더 후 클릭 문제를 실제 QA Release에서 해결·검증했다. 기존 카드 전체를 공식 `ListWidget` 단일 항목으로 감싸 안정적인 collection template / fill-in 경로를 사용한다. 정확한 목적지는 계정별 command로 저장하고, background에서는 일반 feed wake만 열어 인증 가드 전에 개인 상세나 작성 시트가 열리지 않게 했다. native source와 vendor patch를 수정하지 않았다. 최신 FREE/ACTIVE·라이트/다크·기존 세 크기·cold 상세/생성/복귀·로그아웃/계정 전환을 통과했다.
**현재 최종 AAB/IPA 생성과 앱 main 머지는 완료되지 않았다.**

## 사용자가 만나는 흐름

받은 콕은 별도 received 목록을 중복 유지하지 않고 기존 알림함에 통합했다.
현재 export 이름은 **`NotificationList`**이며 `NotificationList.Item / Empty / Error / Loading`으로
관련 항목과 상태를 응집한다. 보낸 콕은 **`SentNudgeList`**와 같은 이름의 namespace 상태를 사용한다.
`/nudges?direction=received`는 `/notifications`, `direction=sent`는 `/nudges/sent`로 Redirect하여
기존 링크를 유지한다. 제거된 중간 구현 `NudgeList`를 현재 컴포넌트로 문서화하지 않는다.

콕 상세는 interaction과 me Query를 읽고 세 답장 버튼을 명시적으로 구성한다.
답장을 보내는 것만으로 할 일이 완료되지 않는다. 완료는 기존 할 일 상세에서 직접 한다.
완료된 공개 할 일의 소유자는 `NudgeThanksButton`으로 친구 목록을 확인하고 감사를 보낸다.
감사 preview는 첫 페이지의 `throughNudgeId`를 다음 페이지에도 유지한다. 화면에는 전체 대상 수를
표시하고, recipients는 실제로 받은 페이지에서 평탄화한다. 다음 페이지 오류는 기존 목록을 유지하며
목록 하단에서 재시도한다. 감사 성공 화면은 mutation 성공 상태를 먼저 읽어 query 갱신 중에도 유지한다.

## 책임 경계와 예측 가능한 Props

| 위치                          | 현재 소유하는 책임                                    | 소비하는 경계                                              |
| ----------------------------- | ----------------------------------------------------- | ---------------------------------------------------------- |
| Model / Policy                | Zod schema와 `z.infer`, URI/상태/TTL/권한의 순수 판단 | 원시 입력과 호출자가 제공한 시간·계정                      |
| Mapper / Service              | 공유 wire 검증, ISO→Date, HTTP와 domain 변환          | 기존 `HttpClient`, shared validators/errors                |
| Query Options                 | Query key·AbortSignal·커서·mutation invalidation      | DI의 기존 TodoNudgeService/NotificationService             |
| Presentation                  | 라벨·색상·JSX·오류/빈 상태·Href 변환                  | domain 모델·순수 Policy와 공용 UI                          |
| Repository                    | 동기 저장 값의 파싱·stable snapshot·조건부 삭제       | 기존 `SyncStorage` 및 feature subscription 포트            |
| Bridge / shared infra adapter | 플랫폼 SDK·MMKV·AppState·UUID·앱 열기                 | `WidgetBridge`, `WidgetNavigationStorage`, `ErrorReporter` |
| Bootstrap                     | DI·Provider 순서·인증 이후 앱 진입                    | feature 저장소·표준 Query observer·Expo Router             |

모델은 React, Expo Router, native SDK, 서버 Entity/Prisma 타입을 import하지 않는다.
`NudgeInteractionPolicy.getStatus`는 원시 boolean으로 조립한 순수 함수에서 domain 상태 enum을 얻으며,
그 상태의 문구와 색상은 `SentNudgeList.Item`에서 결정한다. `isReplyable / isThankable*`은 boolean을
반환한다. 위젯 Policy는 호출자가 전달한 시간·계정을 판단한다. `Date.now`, `randomUUID`,
`AppState.currentState` 같은 외부 읽기는 adapter/entry 경계에서 제공한다. `this` bind에 의존하지 않는다.

`NotificationList.Item`은 기존 `NotificationItem`의 `ComponentProps`를 그대로 받는다.
`SentNudgeList.Item`은 `nudge: NudgeInteraction`을 받는다. `NudgeThanksButton`은
`Omit<ComponentProps<typeof Button>, 'children'> & { todoId: number }`를 사용하며 원본 `onPress`를
호출한 뒤 기존 Overlay에 Sheet를 연다. Sheet도 기존 `ModalBottomSheet` Props를 확장한다.
`Recipient / Recipients / Empty / Error / Loading`은 해당 감사 화면에 응집하고, 공용 시트 엔진을 새로 만들지 않는다.

일반 알림 section·친구·할 일 컬렉션은 데이터 순회로 렌더링한다. 의미가 다른 답장 버튼과
고정된 캘린더 슬롯은 화면에서 읽히는 명시적 구성을 유지한다. `ts-pattern`은 실제 상태/union 분기에,
`es-toolkit`은 실제 컬렉션 변환에 사용한다. 한 줄 boolean까지 불필요한 분기로 감싸지 않는다.

## 서버 상태·URL·Provider·Analytics

서버 상태는 TanStack Query에 두고 응답을 화면 `useState`나 Context에 복사하지 않는다.
알림 category, feed 날짜, 검색, 위젯 생성 action은 Expo Router의 지역 search schema로 검증하고
`router.setParams`로 변경한다. `useWidgetAppEntry`의 전역 pathname/search 읽기는 현재 목적지가 이미
표시됐는지 판단하는 읽기 전용 관측이다. 현재 URL을 새로운 state로 복제하지 않는다.
초기 URL 대기 값과 Android pending command는 인증 복원 이전의 일회성 진입 요청이며 소비 뒤 제거한다.

공통 Provider는 [AppProviders](../../src/bootstrap/providers/app-providers.tsx)에서
Gesture/Keyboard → FontScale/Language/Theme/HeroUI → Query → DI → LocalDate → Auth →
RevenueCat/Notifications → BottomSheet/ErrorBoundary/Overlay 순서로 조립한다.
LocalDateProvider는 전역 한 번, CalendarProvider는 feed 공통 layout,
FeedDateProvider는 각 leaf의 controlled 날짜를 사용한다. 인증 영역의 WeatherSessionProvider를 재사용한다.

[DIProvider](../../src/bootstrap/providers/di-provider.tsx)는 기존 HTTP·Storage·Analytics·ErrorReporter
포트를 조립하고 기존 TodoNudgeService를 확장한다. navigation 저장소도 같은 bootstrap에서 생성해
`useWidgetNavigationRepository`로 전달한다. presentation이 vendor 저장소를 직접 생성하지 않는다.
Android HeadlessJS adapter는 같은 storage id/포트를 사용하지만 React Provider에 의존하지 않는다.

답장 성공은 `nudge_replied { reply_kind }`, 1명 이상에게 감사 전송 성공은
`nudge_thanks_sent { recipient_count }`를 기록한다. 이름·파라미터 타입은
[friend.events.ts](../../src/shared/analytics/events/friend.events.ts)에 응집하고 mutation은 기존
`useTrack`/Analytics 포트를 소비한다. Firebase/Sentry vendor 호출을 feature UI에 추가하지 않는다.
예측하지 못한 오류는 기존 ErrorReporter 포트로 보내고, 서버 4xx는 기존 ApiError/Result 처리와 사용자 복구 동작을 유지한다.

## 위젯 표시·계정 scope·종료 상태 진입

소형은 완료 수/전체 수·진행률·연속 기록과 두 발자국, 중형은 오늘 할 일 2개와 생성,
대형은 주간 7일 달력·오늘 할 일 4개·생성으로 구성한다. iOS의 `AidoTodayList`는 family에 따라
0/2/4행을 사용한다. Android는 기존 이름 `AidoTodaySummary / AidoTodayList / AidoTodayLarge`를 유지한다.
기본 밝은 배경은 `#FFFFFF`, 어두운 배경은 `#171310`, brand는 `#FF6B43`이다.
iOS는 SF `pawprint.fill`, Android는 기존 paw SVG path를 공식 `SvgWidget`으로 표시한다.
Android `TextWidget`에 없는 취소선은 native patch로 만들지 않고 완료 색상과 체크 표시로 표현한다.

공유 snapshot은 `version: 1`을 유지한다. 새 주간/문구 필드는 optional이며 이전 v1을 계속 읽는다.
Android `widget-storage`의 `aido_widget_snapshot_v1` JSON과 개인 목록 소유자를 나타내는 별도
`aido_widget_snapshot_user_id_v1` metadata를 분리한다. 계정 id를 공용 snapshot/iOS timeline payload에
추가하지 않는다. `WidgetSnapshotContext.userId`는 bridge 호출과 dedupe key에만 사용한다.
같은 표시 내용이어도 계정이 바뀌면 새 소유자를 기록한다. logout은 loggedOut snapshot, 소유자 제거,
pending command 제거로 연결한다. 이전 snapshot이나 소유자가 없으면 개인 목록을 추측하지 않고 앱 열기 안내를 표시한다.

```text
실제 Android widget custom click
  → 공식 WIDGET_CLICK / AIDO_WIDGET_NAVIGATE
  → 순수 URI 검증 + 렌더 시 captured userId
  → 동일 MMKV에 { id, uri, userId, createdAt } 저장
  → active: command 소비만 / background·cold: 일반 feed wake로 Linking.openURL
  → auth + 표준 me Query + (app) route 준비
  → useWidgetAppEntry의 RAF / useEffectEvent
  → 최신 명령·현재 계정·5분 TTL 재검증
  → Expo Router.navigate(withAnchor) 또는 이미 표시한 목적지 확인
  → clearIfCurrent로 해당 명령만 제거
```

URI parser는 앱 scheme, feed의 유효 날짜/`today`/`add-todo`, 양의 safe integer todo id만 허용한다.
중복 query key·알 수 없는 query·외부 포트·userinfo·fragment를 거절한다.
미래 timestamp와 5분 만료, 다른 계정, 미인증으로 확정된 요청은 실행하지 않는다.
저장소는 동일 raw 값에 동일 snapshot identity를 반환하여 `useSyncExternalStore` 계약을 지킨다.
늦게 도착한 과거 명령은 최신 `createdAt`을 덮지 않고, 과거 RAF가 최신 명령을 삭제하지 않는다.

종료 상태의 native intent/initial URL이 이전 feed를 반환해도 정확한 command는 별도로 남는다.
최종 QA Release에서 실제 위젯 tap 직전 프로세스 부재·기존 ActivityRecord·launcher PID 유지 조건을 기록하고, 작은 위젯의 홈·중간/큰 상세와 생성·뒤로 복귀를 확인했다. FREE→logout에서 위젯 개인 목록이 비워지고 ACTIVE 로그인 후 해당 계정의 새 1/2 목록만 표시되는 것도 검증했다.

warm에서는 command만 이동을 소유한다. background/cold는 동작 없는 feed wake와 command의 단일 소비로 이동하며, 실제 생성 시트가 한 번 열리고 닫은 뒤 다시 나타나지 않는 것을 FREE/ACTIVE에서 확인했다. 10회 상태 갱신 후 template 3개가 유지되고 최초 clock token 세대는 제거되어 최근 두 세대만 남는 것을 별도로 기록했다. 이 결과를 모든 메모리 누수나 실제 스토어 결제 검증으로 확대하지 않는다.

## 플랫폼과 공식 지원 경로

iOS는 `create-widget-bridge.ios.ts`가 기존 Expo Widgets adapter를 선택한다.
Android는 `.android.ts`가 공식 Android widget adapter를 선택한다. fallback은 noop이다.
등록과 저장소도 플랫폼 파일로 분리해 iOS Metro graph에 Android renderer·task·MMKV widget adapter를
포함하지 않는다. 생성된 Kotlin/Swift 파일, 라이브러리 native source patch, custom compatibility
plugin으로 tap을 고치지 않는다. 공식 Expo config plugin이 기존 package/widget provider 이름을 생성한다.

iOS isolated renderer는 전달받은 props/environment만 사용한다. React hook·앱 Provider·네트워크·
비동기 작업을 넣지 않는다. Android renderer도 props로 공식 widget tree를 만들며
`use no memo`로 해당 library의 tree 수집 경계를 유지한다. 시각·계정·snapshot 읽기는 bridge가 담당한다.

## 날짜·자정·cleanup·실패 격리

`Intl.DateTimeFormat`의 bounded formatter cache로 날짜 키를 만들고 잘못된 Date는 빈 키로 분리한다.
URL date가 없거나 `today`이면 새 날짜를 따르고, 사용자가 고른 고정 날짜는 유지한다.
LocalDateProvider는 다음 로컬 자정 timer를 예약하고 background에서 해제하며 foreground에서
날짜·timezone·UTC offset을 다시 평가한다. iOS는 다음 자정 stale timeline,
Android는 렌더 시 snapshot 날짜 비교를 사용한다. OS/Doze/launcher 정책 때문에 정확한 자정이나
30분 이내에 실제 홈 화면이 갱신된다고 보장하지 않는다.

| 소유자                               | 정리·복구                                                                                 |
| ------------------------------------ | ----------------------------------------------------------------------------------------- |
| LocalDateProvider                    | 자정 timer, AppState/language subscription을 background/unmount에서 정리                  |
| WidgetNavigationStorage / entry hook | MMKV subscription 제거, 예정된 RAF 취소, 새 command·계정·TTL을 실행 직전 재검증           |

  'THANKED',
  'COMPLETED',
  'REPLIED',
  'WAITING',
]);

export function getNudgeInteractionStatus(
  isAvailable: boolean,
  isTodoCompleted: boolean,
  hasReply: boolean,
  isThanked: boolean,
): NudgeInteractionStatus {
  return match({ isAvailable, isTodoCompleted, hasReply, isThanked })
    .returnType<NudgeInteractionStatus>()
    .with({ isAvailable: false }, () => 'UNAVAILABLE')
    .with({ isThanked: true }, () => 'THANKED')
    .with({ isTodoCompleted: true }, () => 'COMPLETED')
    .with({ hasReply: true }, () => 'REPLIED')
    .with({ hasReply: false }, () => 'WAITING')
    .exhaustive();
}

export const nudgeThanksPreviewSchema = z.object({
  todoId: z.number(),
  throughNudgeId: z.number().nullable(),
  totalRecipients: z.number().int().nonnegative(),
  nextCursor: z.number().nullable(),
  hasNext: z.boolean(),
  recipients: z.array(
    z.object({
      id: z.string(),
      name: z.string(),
      profileImage: z.string().nullable(),
    }),

import { z } from 'zod';

const widgetFeedParametersSchema = z
  .object({
    date: z.union([dateSchema, z.literal('today')]),
    action: z.literal('add-todo').optional(),
  })
  .strict();

const widgetNavigationDestinationSchema = z.discriminatedUnion('kind', [
  widgetFeedParametersSchema.extend({ kind: z.literal('feed') }),
  z.object({ kind: z.literal('todo'), todoId: z.string() }),
]);
export type WidgetNavigationDestination = z.infer<typeof widgetNavigationDestinationSchema>;

/** URI는 원시값으로만 해석한다. Router·현재 계정·시계는 호출자가 제공한다. */
export function parseWidgetNavigationUri(uri: string | null): WidgetNavigationDestination | null {
  if (!uri) return null;

  try {
    const parsed = new URL(uri);
    if (!['aido:', 'aido-dev:', 'aido-preview:'].includes(parsed.protocol)) return null;
    if (parsed.username || parsed.password || parsed.hash || parsed.port) return null;

    const path = `/${parsed.hostname}${parsed.pathname}`.replace(/\/$/, '');
    if (path === '/feed') {
      const parameterKeys = [...parsed.searchParams.keys()];
      if (new Set(parameterKeys).size !== parameterKeys.length) return null;
      const parameters = Object.fromEntries(parsed.searchParams);
      const result = widgetFeedParametersSchema.safeParse(parameters);
      return result.success ? { kind: 'feed', ...result.data } : null;
    }

    const todoId = /^\/todo\/([1-9]\d*)$/.exec(path)?.[1];
    return todoId && !parsed.search && Number.isSafeInteger(Number(todoId))
      ? { kind: 'todo', todoId }
      : null;
  } catch {
    return null;
  }
}

  id: z.string().min(1),
  uri: z.string().refine((uri) => parseWidgetNavigationUri(uri) !== null),
  userId: z.string().min(1),
  createdAt: z.number().int().nonnegative(),
});

const isTimestampWithinTtl = (createdAt: number, now: number, ttl: number): boolean =>
  Number.isFinite(now) && createdAt <= now && now - createdAt < ttl;

const isSameAccount = (ownerId: string, userId: string): boolean => ownerId === userId;

export const WidgetNavigationPolicy = {
  isFresh: (command: Pick<WidgetNavigationCommand, 'createdAt'>, now: number): boolean =>
    isTimestampWithinTtl(command.createdAt, now, WIDGET_NAVIGATION_COMMAND_TTL_MS),
  isOwnedBy: (command: Pick<WidgetNavigationCommand, 'userId'>, userId: string): boolean =>
    isSameAccount(command.userId, userId),
  isSameCommand: (first: WidgetNavigationCommand, second: WidgetNavigationCommand): boolean =>

  const getPendingCommand = (): WidgetNavigationCommand | null => {
    const raw = storage.getString(WIDGET_NAVIGATION_COMMAND_KEY);
    if (raw === cachedRaw) return cachedCommand;

    cachedRaw = raw;
    cachedCommand = null;
    if (raw === undefined) return null;

    try {
      const value: unknown = JSON.parse(raw);
      const result = widgetNavigationCommandSchema.safeParse(value);
      cachedCommand = result.success ? result.data : null;
    } catch {
      // 오래되거나 손상된 저장 값은 탐색 명령으로 취급하지 않는다.
    }
    return cachedCommand;
  };

  return {
    getPendingCommand,
    subscribe: (listener) => storage.subscribe(WIDGET_NAVIGATION_COMMAND_KEY, listener),
    store: (command) => {
      const result = widgetNavigationCommandSchema.safeParse(command);
      if (!result.success) return false;
      const current = getPendingCommand();
      if (current && current.createdAt > result.data.createdAt) return false;
      storage.set(WIDGET_NAVIGATION_COMMAND_KEY, JSON.stringify(result.data));
      return true;
    },
    clearIfCurrent: (command) => {
      const current = getPendingCommand();
      if (
        command === null
          ? current !== null || cachedRaw === undefined
          : current === null || !WidgetNavigationPolicy.isSameCommand(command, current)
      ) {
        return false;
      }
      storage.delete(WIDGET_NAVIGATION_COMMAND_KEY);
      return true;
    },
  };
