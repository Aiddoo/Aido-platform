# 1.14.0 클라이언트: 날씨 화면 v2, 오프라인, 구독 안내, 개발 빌드 분리

기준: `develop...chore/release-1.14.0` 스택(`stack:1.14.0`). 코드에서 확인한 내용만 적었고 실기기 검증 결과는 포함하지 않는다. 서버는 [1.14.0 서버](../../../../docs/releases/1.14.0.md).

## 요약

- 날씨 화면을 서버 v2 리포트(`/v2/weather`)로 다시 만들었어요. Skia 하늘 장면, 아이두 브리핑, 비와 겹친 할 일 옮기기, 특보·분 단위 강수·상세 타일·해와 달·대기질을 보여 줘요.
- 오프라인에서 안내 배너를 띄우고, 로그아웃은 기다리지 않아요. 화면에 보이는 읽기 데이터는 암호화 저장소에 남겨 오프라인 재실행 때 복원해요.
- 스토어를 쓸 수 없을 때 구독 화면이 오류 대신 안내와 문의로 이어져요.
- 개발 빌드가 운영 앱과 다른 번들 ID(`.dev`)로 설치되고, Firebase·Kakao 설정을 환경별로 나눴어요.
- 프리미엄 게이트가 서버 권한 스냅샷을 따르고, 결제·초대 보상 기간을 같은 방식으로 보여 줘요. 프리미엄이 끝나면 관련 데이터를 다시 받아요.
- 앱 전체 오류 화면(다시 시도·앱 다시 시작·문의)을 더하고, 화면 이름을 라우트 템플릿으로 보내 분석에 실제 id가 남지 않아요.

## 구조 변경 요약

### 날씨 화면 v2

- 데이터: `features/weather`의 리포트·위치 등록 계층(`weather-report.model`, `weather-location.service`, `get-weather-report-query-options`).
- 장면: `components/weather-scene/`의 구름·비·눈·안개·번개·별·해 빛 레이어와 하늘 그라디언트를 Skia 캔버스로 그려요(`@shopify/react-native-skia` 추가). 팔레트는 `constants/weather-scene-palette.ts`, on-sky 색은 `use-on-sky-color`.
- 구성: `weather-hero`, `weather-briefing`, `weather-briefing-chip`, `hourly-forecast`, `daily-forecast`, `next-hour-precipitation`, `weather-alerts`, `weather-detail-grid`, `weather-sun-moon`, `weather-air-quality`. 곡선·원형 계산은 `d3-shape`와 `utils/view-models/`로 분리했어요.
- 넓은 화면(iPad·Duo 펼침)은 지금 날씨와 예보·상세 두 단이에요.
- 히어로: 기온 숫자의 글리프 높이가 iOS와 Android에서 달라 플랫폼별 em 오프셋으로 지명·날씨 줄과의 간격을 맞췄어요(`weather-hero.tsx`). 최고/최저는 한 칸 간격으로, 숫자는 `tabular-nums`(고정폭)이에요.
- 날씨 고양이 이미지를 불러오지 못하면 날씨 아이콘으로 대신 그려요.
- 범위 제한과 반복은 es-toolkit `clamp`·`range`로 바꿨어요.

### 오프라인·영속 캐시

- `bootstrap/providers/online-manager.ts`가 `expo-network`(`shared/infra/network`) 상태를 React Query `onlineManager`에 연결하고 전환마다 breadcrumb를 남겨요. 배너는 `shared/ui/offline-banner`(`AppProviders`에 한 번).
- `features/auth/utils/log-out-device.ts`가 로그아웃을 최선 노력으로 처리하고, `sync-notification-badge.ts`는 오프라인이면 배지 동기화를 건너뛰어요.
- 영속 캐시(`query-cache-persistence.ts`, `shared/constants/query-persistence.ts`):
  - 암호화 MMKV에 저장하고, 사용자 id별 키에 둬요. 주인이 바뀌거나 로그아웃하면 지워요. 암호화 저장소를 열지 못하면 저장하지 않아요. 암호화 이전의 평문 캐시는 삭제해요.
  - `meta.persist: true`로 opt-in한 성공 조회만 저장해요(`PERSISTED_QUERY_OPTIONS`, 현재 10개 파일에서 사용). 토큰·결제·배지는 제외, 뮤테이션은 저장하지 않아요.
  - 최대 24시간, buster는 스키마 버전 + 앱 버전이라 앱 버전이 바뀌면 버려요.
  - 복원한 데이터는 서버에 닿지 못한 낙관적 반영일 수 있어 stale로만 표시해요(`query-provider.tsx`).

### 구독 스토어 불가 처리

- `offerings-availability.ts`: 스토어를 쓸 수 없는 실패는 안내 화면(`subscription-store-unavailable`)으로, 그 밖의 실패는 오류 경계로 던져요.
- 신호: 배포 빌드의 설정 문제는 Sentry error, 일시 응답 불가는 warning이고 개발 빌드는 로그만 남겨요. 진단 코드별로 세션당 한 번만 보고해요(`get-offerings-query-options.ts`).
- 구독 관리를 열지 못하면 문의로 잇는 토스트를 띄워요(`use-open-subscription-management.ts`).

### 개발 빌드 번들 분리

- `app.config.ts`: development의 번들 ID·패키지명을 `com.aido.mobile.dev`로 분리했어요(이전에는 운영과 같았어요). 한 기기에 함께 설치되고 키체인·푸시 토큰이 분리돼요.
- Firebase iOS plist는 환경별 파일이고 EAS 환경마다 같은 이름 `GOOGLE_SERVICES_INFO_PLIST`로 등록해요([EAS_SECRETS.md](../EAS_SECRETS.md)). Android `google-services.json`은 `.dev`·`.preview` 앱을 추가한 파일이 필요해요.
- Kakao: 저장소의 `.env.development`에 개발용 네이티브 앱 키가 별도로 있어요. EAS `development` 환경에 등록됐는지는 확인하지 못했어요.
- 로컬 기기 빌드가 자동 서명되도록 Apple 팀 ID를 prebuild에 넣어요.

### 알림 딥링크

- `notification-destination.ts`가 `/weather/reschedule?todoIds=…&reason=rain|heat`를 읽어 옮기기 시트를 열어요. 할 일 id가 50개를 넘으면 링크를 버리고 날씨 화면으로 가요(서버 vocabulary 기준).

### 제거된 레거시

- v1 날씨 클라이언트: 옛 날씨 카드 구성, `weather-scene-palette.ts`(constants로 이동), `use-reschedule-todo-ids-param`(`utils/navigation/weather-reschedule-href`로 대체), `use-reschedule-todo-mutation-options`와 테스트, 옛 날씨 아이콘 SVG 7개와 `icons.ts`의 해당 export, `use-draft-storage-bootstrap`.

## 호환성

- 서버 `/v1`은 유지되어 1.13.1 이하 앱은 그대로 동작해요. 1.14.0 앱은 `/v2/weather`만 써서 서버가 먼저 배포돼야 해요.
- 개발 빌드의 번들 ID가 바뀌므로 기존 개발 빌드는 별도 앱으로 설치돼요. 운영·preview 번들 ID는 그대로예요.
- 의존성: `@shopify/react-native-skia`, `d3-shape`, `expo-network`, `@tanstack/react-query-persist-client`, `@tanstack/query-async-storage-persister` 추가, `react-native-purchases` 10.15.1 → 10.16.0.

## 남은 과제

- 푸시 문구의 기온이 °C 고정이라 앱의 °F 설정과 맞지 않아요.
- 실기기·시뮬레이터 QA 결과는 이 문서에 없어요.
- Kakao 개발 키의 EAS `development` 환경 등록 여부 확인이 필요해요.
- 소셜 가입은 서버 응답에 신규 가입 여부가 없어 `auth_login`으로만 남아요. 서버 `isNewUser` 필드가 생기면 `auth_signup`으로 나눠요.
- 측정 계획과 GA 콘솔 설정은 [analytics-measurement-plan](../analytics-measurement-plan.md)에 있어요.
