# 1.15.1 클라이언트: 카테고리 삭제 선택·푸시 정리·넓은 기기·새로운 기능 목록

기준은 `stack:1.15.1`의 `apps/mobile` 커밋이다. 서버 변경은 [서버 CHANGELOG](../../../api/CHANGELOG.md), 이벤트는 [analytics 측정 계획](../analytics-measurement-plan.md)을 따른다. 코드와 테스트에서 확인한 내용이고 실기기 확인은 [출시 전 확인](#출시-전-확인)에 남는다.

## 요약

- **카테고리 삭제 선택**: 삭제를 누르면 미리보기(`GET /v1/todo-categories/:id/deletion-preview`)를 받아 삭제 시트를 연다. 할 일·반복이 있으면 "옮기고 삭제"(기본, 정렬이 가장 앞인 카테고리)와 "할 일도 함께 삭제"를 고른다. 없으면 확인 창만, 마지막 카테고리는 이유와 함께 막는다. 지우는 동안 목록에서 미리 빼지 않고 응답으로 목록을 고친 뒤 결과를 토스트로 알린다. 미리보기와 달라 거절되면(`TODO_CATEGORY_0854`·`0855`·`0856`) 미리보기를 다시 받는다. 서버 규칙: [카테고리 삭제](../../../api/docs/todo-categories.md).
- **낙관적 변경**: 실패하면 그 변경만 되돌린다. 카테고리 고치기가 실패해도 그사이 바뀐 할 일 수가 남고, 댓글 하트를 연타해도 앞 응답이 뒤 하트를 되돌리지 않으며, 알림을 이어 읽다 하나가 실패해도 배지가 깜빡이지 않고, 친구 둘을 함께 끊다 하나가 실패하면 그 친구만 돌아온다. 응답 전 임시 할 일·하위 할 일·카테고리는 요청을 보내는 체크·버튼을 끈다. 카테고리를 만들거나 고치면 목록 재조회를 기다리지 않고 시트가 닫힌다.
- **하위 할 일 끌기**: 막 만든 하위 할 일을 바로 끌면 임시 id로 순서(`PATCH /items/reorder`)를 보내 400이 났다. 마지막으로 그린 목록을 읽고, 임시 행이 있으면 끌기를 끄고, 섞이면 보내지 않고 서버 순서로 돌린다. 할 일·카테고리 순서도 같은 훅이다.
- **키보드·시트**: 높이 720 미만의 낮은 창(접은 iPhone Duo 등)에서 카테고리 시트의 색을 한 줄로 밀고, 키보드가 시트를 올릴 때는 오른쪽 레일의 상태 표시 아래에서 멈추지 않고 위쪽 safe area까지 올라가 키보드 위에 이름·색·확인이 함께 보인다. 시트 내용은 레일만큼 들여 상태 표시와 겹치지 않고, 누른 색은 다 보일 만큼만 줄을 민다. 키보드 시트 바깥 탭은 `useTapGesture`이고 닫힌 시트는 뒤 화면의 탭을 가로채지 않는다. 확인 창 제목·설명이 한글 단어 중간에서 줄을 바꾸지 않는다.
- **달력 머리**: 좁은 칸·영어·큰 글자에서 한 줄(제목·오늘·주|월·이동)과 두 줄(제목·오늘 / 주|월 ‹ ›) 중 하나를 그리기 전에 정한다(`getCalendarHeaderLayout`). 주·달을 넘겨도 배치가 바뀌지 않는다. 한국어 기본 크기 휴대폰·iPad는 지금처럼 한 줄이다.
- **넓은 기기**: Android는 창의 짧은 변이 600dp 미만(휴대폰·접은 바깥 화면)일 때만 세로로 묶고 큰 화면은 방향을 푼다. iPhone은 세로, iPad는 네 방향 그대로다. 밀도가 다른 폴더블 화면을 오가도 Activity를 다시 만들지 않아 보던 화면과 입력이 남는다. iPad 탭 사이드바가 열려도 목록·상세 칸을 탭이 받은 폭(`usePaneSizeClass`)으로 나눈다. iPhone Duo 세로에서 친구 줄은 레일 밑까지 밀리고 칸만 레일을 피한다. 규칙: [넓은 화면과 기기](../../.claude/ui-components.md#넓은-화면과-기기).
- **푸시**: 허용한 기기가 토큰을 받지 못해도 마지막으로 보고한 토큰으로 보고해 등록을 지킨다. 온라인 로그아웃 없이 세션이 끝나면(갱신 토큰 만료·오프라인 로그아웃) 기기 id와 토큰으로 이 기기의 등록을 푼다(`POST /v1/notifications/push-devices/unregister`). 앱 아이콘 배지는 알림함의 안 읽은 수 하나로 맞춰 다른 기기에서 읽은 알림도 반영된다. 앱을 쓰는 중 받은 알림은 그 화면을 이미 보고 있으면 배너 없이 알림 센터에만 남는다. 같은 푸시 탭은 한 번만 연다(처리한 응답 id 최근 20개). 설정 문구가 계정 전체 적용, 기기 권한은 이 기기만, 야간 설정은 혜택·친구 알림만 막고 직접 정한 리마인드는 제시간에 온다는 것을 알린다. 상세: [푸시 알림 클라이언트](../push-notifications.md).
- **새로운 기능**: 가입 시점과 상관없이 아직 보지 않은 계정에 한 번 자동으로 연다(새 계정도 알림 화면 다음에 1.15.0 소개를 본다). 알림 화면을 열지 정해지고 닫힌 뒤에만 열고, 말풍선은 그다음이다. 목록은 출시마다 쌓이는 줄과 최근 두 출시의 소개로 나누고, 줄마다 "v1.15.0 · 11월 10일 업데이트"처럼 버전·날짜를, 아래에 "전체 업데이트 내역"(패치 노트)을 둔다. 말로 할 일 만들기 카드는 오늘 피드에서 시트를 연다. 1.15.1은 새 소개 줄을 더하지 않는다. 운영 순서: [새로운 기능 출시](../whats-new-release.md).
- **시작 체크리스트**: 새로운 기능 캠페인에서 떼어 가입 7일 동안(`user.createdAt` 기준) 계정만 보고 보인다.
- **서버 값 그대로**: 여러 날 할 일의 날짜별 완료, 알림함 `navigation`, 날씨 브리핑의 영향받는 할 일·옮길 시각, 메모 AI의 "이번 주말" 반복, 반복 상한 안내의 한도(`details.limit`)를 앱이 다시 계산하지 않는다. 주차·기간 라벨은 앱 언어로 만들어 언어를 바꾸면 지난 항목도 바뀐다.

## 그 밖의 변경

- **위치 권한(Android)**: 대략적 위치(`ACCESS_COARSE_LOCATION`)만 받는다. expo-location이 더하는 `ACCESS_FINE_LOCATION`은 `blockedPermissions`로 뺀다([Expo 문서](https://docs.expo.dev/versions/v58.0.0/sdk/location/)). 날씨는 서버가 약 5km 격자(기상청)와 칸 중심 좌표(WeatherKit)로만 쓰므로 정확도가 결과를 바꾸지 않는다. Play는 버전 코드 125를 데이터 보안의 위치 미신고로 거부했다. 정확한 위치는 2027-01-27부터 별도 권한 신고가 의무라([Play 위치 정책](https://support.google.com/googleplay/android-developer/answer/17033915)) 처음부터 받지 않는다. iOS는 그대로이고 사용자가 시스템 창에서 정확한 위치를 끌 수 있다.
- **관측**: Sentry 세션 녹화는 0, 오류 녹화는 0.2다(무료 월 50개를 넘겨 버려지던 녹화). trace 헤더(`sentry-trace`·`baggage`)는 API 출처에만 붙여 서버 오류와 묶고, `sendDefaultPii: false`다.
- **라이브러리**: i18next 27·react-i18next 18, TanStack Query 5.107.1, Expo SDK 58 권장 버전(`expo-asset`)으로 올리고 드러난 deprecated API(Query `ensure*`·`prefetch*`, Worklets `runOnUI`, Gesture 빌더, datetimepicker `onChange` 등)를 바꿨다. `react-native-purchases`는 결제 오류 분류가 바뀌는 11 대신 10.16.0에 둔다.
- **구조 정리**: 모든 Policy가 모델 전체를 첫 인자로 받고 모델 일부(폼 값·`select` 결과) 규칙은 Policy 밖 순수 함수로 둔다. `check:conventions`가 Policy 첫 인자 모양과 도메인 모델 import를 막는다. 카테고리(카테고리·삭제 미리보기)와 알림(알림·받은 푸시·누른 응답·처리 기억) Policy를 모델마다 나눴다. 엔티티 id 검사는 `@aido/api/vocabulary`의 `ENTITY_ID_PATTERN`이다.
- **DI**: 운영과 테스트가 같은 `createAppContainer(ports)`로 Service를 조립하고, 테스트는 stub 포트만 넣는다. 로거·QueryClient·보안 저장소·토큰 갱신기·결제 SDK·HTTP 클라이언트는 `composition-root`가 프로세스에 한 번 만들어, 루트 오류 화면의 "다시 시도"가 로그인을 잃거나 결제를 다시 설정하지 않는다. 시작 정리는 렌더가 아니라 effect에서 한다. 할 일을 만든 기능은 `todo-created` 이벤트로 알리고 시작 체크리스트가 받아 기록해, `check:conventions`의 위층 허용 목록이 0이다. 상세: [구조 문서](../../.claude/architecture.md).
- **고마움 현황**: 할 일 완료를 저장하는 동안에는 고마움 현황을 묻지 않아, 완료 직후 "고마움 현황을 불러오지 못했어요" 카드가 남던 문제가 없어졌다(서버도 완료 전 조회에 빈 미리보기로 답해 1.15.0 이하 앱도 고쳐진다). 실제 실패는 인라인 안내(다시 시도·문의하기)로 보인다.
- **친구 피드**: 보던 친구가 친구를 끊으면 오류 화면 대신 "이제 친구 피드를 볼 수 없어요" 안내와 "내 피드로 가기"를 보이고 오류로 보고하지 않는다(`FOLLOW_0906`은 예상된 상태).
- **루트 오류 화면**: 앱의 다른 오류 화면과 같은 그림·글자·간격을 쓰고, Sentry에는 `root_error_boundary` 태그로 따로 남는다.
- **E2E**: Maestro 흐름을 `.maestro` 기능별 흐름·subflow·선택자 한 곳으로 다시 짰다([Maestro](../../.maestro/README.md)).

## 호환

- **서버 계약**: 출시 앱이 쓰는 계약은 바뀌지 않는다(서버는 추가만 했다). 1.15.1 앱이 새로 쓰는 미리보기·`todoHandling`·기기 해제는 1.15.1 서버에 있다. 서버를 먼저 배포한다. 1.15.0 서버면 미리보기가 404라 옮기기만 보이고 출시 앱처럼 옮길 곳만 보내며, 기기 해제는 404를 조용히 끝낸다.
- **본 기록 키**: 새로운 기능·말풍선의 본 기록 키는 그대로다. 1.15.0 앱이 남긴 기록을 읽어 이미 본 소개를 다시 열지 않는다.
- **시작 체크리스트 키**: 진행 키를 계정별 `aido_activation_v2:{accountId}`로 바꾸고 1.15.0 이하의 `aido_activation_v1:*`는 앱 시작 때 지운다. 가입 7일 안 계정은 기기의 체크 기록이 비지만 단계는 서버 할 일 기록으로 다시 채워진다.
- **기기 저장**: 보고한 토큰과 해제 요청을 SecureStore `pushRegistration`에 더한다. 저장 캐시 스키마 버전은 그대로다.
- **분석 이벤트**: `activation_completed`는 가입 7일 안에만 남기고 `campaign_id`가 빠진다. `push_notification_opened`에 `app_state`(cold·background·foreground)를 더한다. 카테고리 삭제는 `category_delete_sheet_viewed`·`category_delete_cancelled`·`category_deleted`다.
- **위치 권한**: 정확한 위치를 허용했던 Android 사용자는 대략적 위치 허용이 함께 남아 있어 업데이트 뒤 다시 묻지 않는다. 서버는 좌표 정밀도와 상관없이 같은 계약으로 받는다.
- **캠페인 설정**: 1.15.1 앱은 `FEATURE_DISCOVERY_LAUNCHED_AT`을 읽지 않는다. 서버는 1.15.0 이하 앱을 위해 계속 보낸다.

## 출시 전 확인

- **빌드·제출**: [배포 전 체크리스트](../../DEPLOYMENT.md#배포-전-체크리스트). 앱 버전은 `package.json`의 1.15.1이고 빌드 번호는 EAS remote가 올린다.
- **Play 데이터 보안**: 위치 > 대략적인 위치를 수집함·공유 안 함·선택·앱 기능으로 신고한다. 정확한 위치는 신고하지 않는다. 번들의 매니페스트에 `ACCESS_FINE_LOCATION`이 없는지 확인한다.
- **새로운 기능**: [출시 체크리스트](../whats-new-release.md#출시-체크리스트). 이번 출시는 캠페인 값을 바꾸지 않는다.
- **E2E·수동 확인**: `pnpm --filter @aido/mobile e2e`와 [자동화하지 않는 것](../../.maestro/README.md#자동화하지-않는-것-수동-확인).
- **기기**: 접은·펼친 iPhone Duo와 Android 폴더블에서 방향·칸·카테고리 시트, iPad 탭 사이드바를 연 상태의 칸 폭, 영어·큰 글자 달력 머리, 다른 기기에서 읽은 알림의 배지, 로그아웃한 기기에 이전 계정 푸시가 오지 않는지 본다.
