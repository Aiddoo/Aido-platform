# 다국어

서버가 만드는 문구(푸시·메일·오류 message·AI 지시문)를 더하거나 언어를 추가할 때 읽는다. 날짜·언어 공통 규칙은 [날짜·시간·언어](../../../docs/conventions/dates.md), 앱 문구는 [모바일 i18n](../../mobile/docs/dates-and-i18n.md)에 있다.

## 언어 결정

언어 규칙의 정본은 이 절이다. 앱은 기기 언어가 한국어면 `ko`, 그 밖의 언어(감지하지 못한 경우 포함)는 `en`을 앱 언어로 쓰고(사용자가 고르면 그 값), 모든 요청에 `Accept-Language: <앱 언어>`를 보낸다. 그래서 출시 앱이 보내는 값은 `ko`·`en`뿐이다.

| 쓰는 곳                                                                                                         | 함수                                                                       | 헤더 없음                                            | 지원하지 않는 언어(예: `ja`)      |
| --------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- | ---------------------------------------------------- | --------------------------------- |
| 응답 문구(오류 `message`, `@nestjs/i18n`), 요청에 답해 보내는 코드 메일                                         | `resolveResponseLocale`(`RequestClientLocaleResolver`·`@ResponseLocale()`) | `ko`                                                 | `en`                              |
| 저장하는 앱 언어(`UserPreference.locale`, 푸시 기기 보고), 가입 때 기본 카테고리 이름, 알림함 렌더, 날씨 리포트 | `RequestClient.locale`(`@Locale()`) = `requestedAppLocale`                 | `null`: 저장값 유지, 알림함은 저장 문구, 날씨는 `en` | `en`(버전 없음·1.4.0 미만만 `ko`) |
| 푸시·리마인더·배치 문구                                                                                         | `resolveRecipientLocale`(저장된 `UserPreference.locale`만 넘긴다)          | 저장값이 없으면 `ko`                                 | `en`                              |

- `ko`·`en`은 어디서나 그대로다. 값이 없을 때 `ko`인 것은 언어를 보고하지 않던 옛 앱 사용자가 한국어 사용자였기 때문이다.
- 언어 규칙의 원본은 `@aido/api/vocabulary` 하나이고 앱과 서버가 함께 쓴다. `SUPPORTED_LOCALES`·`DEFAULT_LOCALE`(`ko`)·`FALLBACK_LOCALE`(`en`)·`LOCALE_FALLBACKS`(언어 코드만으로 고를 수 없는 태그 표, 지금은 비었고 `I18nModule`의 `fallbacks`로도 넘긴다. 키는 소문자 BCP 47 태그(`zh-tw`)로 적는다. `findSupportedLocale`은 소문자로 바꾼 요청 태그로 키를 대소문자까지 똑같이 찾고, `@nestjs/i18n` 0.0.x는 대소문자를 무시해 맞추되 BCP 47 태그가 아닌 키는 부팅 때 거부한다)·`Localized<T>`·`findSupportedLocale`·`resolveSupportedLocale`(없음 `ko`, 지원하지 않는 언어 `en`)이다. 태그는 `language[-script][-region]`을 직접 나눠(Hermes에 `Intl.Locale`이 다 없다) 전체 태그 → `LOCALE_FALLBACKS` → 언어 코드 순으로 찾는다.
- 예외는 `resolvePreI18nAppLocale` 하나다. `X-App-Version`이 없거나 1.4.0보다 낮은 요청(1.10.0 이하 앱과 앱 밖 클라이언트, 앱은 1.10.1부터 버전을 보낸다)만 지원하지 않는 언어를 `ko`로 저장한다. 1.4.0 전 앱은 Accept-Language를 직접 보내지 않았지만 iOS가 기기 언어(`ja-JP` 등)를 붙였고 화면은 한국어뿐이었다. 1.4.0~1.10.0 앱은 `ko`·`en`만 보내 영향은 지원하지 않는 언어뿐이다(`request-client.ts`, 제거 조건은 [호환](../../../docs/conventions/compatibility.md)).
- 언어는 경계(`RequestClient`, 수신자 언어 reader, job payload)에서 한 번 정해 필수 인자로 넘긴다. 저장된 설정이 필요한 곳은 두 번째 경계 하나에서 정한다. AI(글·메모 파싱, 빠른 계획, 말로 메모)는 `@Locale()` 값을 `requestedLocale: SupportedLocale | null`(null은 보내지 않음)로 UseCase까지 넘기고 `resolveRequestLocale`(헤더 → 저장된 언어)에서 한 번 정한다. 날씨 리포트는 controller의 `resolveWeatherReportLanguage`(null이면 `en`)에서 한 번 정한다. 문구 함수에 `locale?`·`locale = DEFAULT_LOCALE`·`?? DEFAULT_LOCALE`을 두지 않는다. 여러 수신자는 `getLocales`·`findUserLocales`가 돌려주는 `RecipientLocaleOf`(저장값 없는 수신자도 `resolveRecipientLocale` 규칙)로 읽는다.
- 표시 언어는 글자만 바꾼다. 언어로 시간대·오늘·주 시작을 바꾸지 않는다.

## 카탈로그 (`@nestjs/i18n`)

- 위치: `apps/api/src/i18n/<locale>/<namespace>.json`. 지금 namespace는 `email`·`errors`·`notification`이고 기준 언어는 `ko`다. `nest-cli.json` `assets`로 dist에 복사한다.
- [AppI18nModule](../src/platform/i18n/i18n.module.ts)이 카탈로그를 읽는다(`responseHeaders: false`라 `Content-Language`·`Vary`를 붙이지 않는다). 패키지(0.0.x)는 `platform/i18n` 밖에서 직접 쓰지 않는다.
- 타입: `i18n-translations.ts`가 ko 카탈로그로 `declare module "@nestjs/i18n" { interface I18nTypes … }`를 등록한다. `catalog-parity.spec`이 언어 사이 키·자리표시자를 비교한다.
- 자리표시자는 `{name}`, 복수형은 CLDR 범주(`one`·`other`)다. 한국어 조사(을/를)는 `es-hangul` `josa`로 미리 붙여 인자로 넘긴다(`shared/application/messages/locales/ko/notification-grammar.messages.ts`).

## 언어별 자원 세 가지

- 번역할 글: 위 카탈로그 JSON.
- 언어마다 코드가 다른 자원(조사 같은 문법, AI 지시문·예시): `<slice>/application/messages/locales/<언어>/<이름>.messages.ts`. 언어마다 같은 파일 이름을 두고 slice가 `satisfies Localized<…>` 표로 모은다.
- 메일: 아래 표의 React Email 템플릿과 `email` 카탈로그.
- 언어마다 다른 값은 `Localized<T>` 표나 ts-pattern `.exhaustive()`로 고른다. `locale === "ko"` 같은 비교는 Oxlint `aido/no-locale-literal-comparison`이 막는다. `locale-folders.spec`은 `src/i18n`과 모든 `locales/` 폴더의 하위 폴더가 `SUPPORTED_LOCALES`와 같고 파일 이름이 같은지 본다(숨김 파일 `.DS_Store`는 건너뛴다). ls-lint는 `locales/<언어>/`에 `.messages.ts`만 두고 폴더 이름은 `language[-Script]`(`ko`·`zh-Hant`)만 받는다. 지역 폴더(`pt-BR`)는 ls-lint 규칙과 `LOCALE_FALLBACKS` 항목을 함께 더할 때만 만든다. 테스트 파일은 `locales/**`에 두지 않고 slice의 `messages/`에 둔다.

## 문구별 규칙

| 문구            | 규칙                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 오류 `message`  | `errors.json`에 `ErrorCode`별 문구. ko는 `Errors` 합니다체와 바이트 단위로 같고(`catalog-parity.spec`), 출시 계약이라 해요체의 보조 용언 붙여쓰기에서 빠진다(`확인해 주세요`·`받아 주세요`, `THROTTLED_DESCRIPTION`) en은 앱 `errors` 카탈로그의 영어와 같은 표현이다. `GlobalExceptionFilter`가 `ErrorMessageTranslator`로 기본 문구만 바꾸고, 던진 곳이 정한 문구와 검증 파이프 Zod 문구는 그대로 둔다. 코드를 더하면 ko·en에 함께 더한다                                                                                                      |
| 푸시            | `notification.json`(`<그룹>.<템플릿>.<variant>`). notification `shared/application/messages`가 같은 JSON을 import해(`notification-copy-catalog.messages.ts`) 요청 밖에서 수신자 언어로 렌더한다. ko 키가 다른 언어에 빠지면 컴파일 오류. 렌더 결과는 `notification-copy-render.messages.spec` 스냅숏으로 고정한다                                                                                                                                                                                                                                |
| 알림함 항목     | `copyKey`·`copyFacts`(언어와 무관한 원본 사실)를 저장하고 조회 때 `renderInboxCopy`가 요청 언어로 다시 렌더한다. `copyKey` 없는 옛 행·모르는 키·맞지 않는 사실·Accept-Language 없는 요청은 저장한 title·body다. 다른 Context가 만드는 알림도 `copyKey`·`copyFacts`를 넘겨야 언어를 바꾼 뒤 다시 렌더되고, 넘기지 않으면 저장 문구로 보인다                                                                                                                                                                                                       |
| 톤              | 앱 UI와 서버 푸시 모두 해요체, 이모지는 알림 하나에 최대 1개. 상세는 [푸시 알림](push-notifications.md#문구와-변형-선택)                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Zod 검증 메시지 | 출시 계약이라 한국어 유지. 앱은 `SYS_0002`로 현지화                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| 메일            | `email.json`의 문구를 React Email 템플릿(`email-messages/infrastructure/templates/<이름>.email.tsx`)이 `@nestjs/mail` 메일 클래스 `EmailTemplateMail`로 렌더한다. 미리보기(`email:preview`)가 Nest 밖에서 돌아 템플릿은 같은 JSON을 `email-copy.messages.ts`로 읽는다. React Email은 부팅 때 불러오지 않고 첫 렌더에서 불러온다. 코드 메일은 요청 언어(identity controller의 `@ResponseLocale()`), 문의·신고는 운영자 언어 `ko`다. 큐에는 렌더한 메일이 담겨 언어를 따로 싣지 않는다. 렌더 결과는 `email-template.mail.spec` 스냅숏으로 고정한다 |
| AI 지시문       | ai-assistance 작업별 언어 파일(`messages/locales/<언어>/<task>-system.messages.ts`·`<task>-examples.messages.ts`)과 `language-policy.messages.ts`. 기존 AI 평가를 통과할 때만 바꾼다([AI](ai.md#평가))                                                                                                                                                                                                                                                                                                                                           |
| 기간 라벨       | 주간(성취 `weekLabel`·리포트 `periodLabel`)은 `shared/domain/time/week-of-month.ts`의 `formatIsoWeekLabel` 하나로 "11월 2주차"/"Week 2 of Nov"(목요일이 속한 달의 몇째 주), 다른 해 주는 "2025년 12월 1주차"(올해는 저장 시간대 기준), 월간은 "2026년 3월"이다. 앱은 `dateRange`·오늘 key로 직접 표시하고 서버 필드는 출시 앱 호환이다                                                                                                                                                                                                           |

문구 자체를 바꾸는 일은 Before/After 표로 따로 올린다. 유입률을 바꾸는 카피 실험은 `ExperimentAssignerPort`로 나눠 측정한다([알림·지표](notifications.md#지표)).

## 언어 추가 절차

1. `@aido/api/vocabulary` `SUPPORTED_LOCALES`에 언어(예: `ja`)를 더한다. `Localized<T>` 표가 빠진 곳을 컴파일 오류로 알려 준다.
2. `src/i18n/<언어>/`와 모든 `locales/<언어>/` 폴더를 `ko`에서 복사해 번역한다. `locale-folders.spec`이 빠진 폴더·파일을 알려 준다.
3. 메일 바닥글은 `https://aido.kr/<locale>/terms`·`/privacy`로 이어지므로 랜딩(Aido-Landing)에 그 언어 경로를 먼저 연다.
4. 모바일 카탈로그를 만든다.

언어 짝 검사(키·자리표시자·복수 범주)가 빠진 곳을 실패로 알려 준다. `UserPreference.locale`은 문자열이라 마이그레이션이 없다. 렌더 결과는 스냅숏(`__snapshots__`)으로 바이트 단위로 확인한다.
