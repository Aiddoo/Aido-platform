# 다국어

서버가 만드는 문구(푸시·메일·오류 message·AI 지시문)를 더하거나 언어를 추가할 때 읽는다. 날짜·언어 공통 규칙은 [날짜·시간·언어](../../../docs/conventions/dates.md), 앱 문구는 [모바일 i18n](../../mobile/docs/dates-and-i18n.md)에 있다.

## 언어 결정

언어 규칙의 정본은 이 절이다. 앱은 기기 언어가 한국어면 `ko`, 그 밖의 언어(감지하지 못한 경우 포함)는 `en`을 앱 언어로 쓰고(사용자가 고르면 그 값), 모든 요청에 `Accept-Language: <앱 언어>`를 보낸다. 그래서 출시 앱이 보내는 값은 `ko`·`en`뿐이다.

| 쓰는 곳                                                                                                         | 함수                                                              | 헤더 없음                                            | 지원하지 않는 언어(예: `ja`) |
| --------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- | ---------------------------------------------------- | ---------------------------- |
| 응답 문구(오류 `message`, `@nestjs/i18n`)                                                                       | `resolveResponseLocale`(`RequestClientLocaleResolver`)            | `ko`                                                 | `en`                         |
| 저장하는 앱 언어(`UserPreference.locale`, 푸시 기기 보고), 가입 때 기본 카테고리 이름, 알림함 렌더, 날씨 리포트 | `RequestClient.locale`(`@Locale()`) = `parseAcceptLanguage`       | `null`: 저장값 유지, 알림함은 저장 문구, 날씨는 `en` | `ko`                         |
| 푸시·리마인더·배치 문구                                                                                         | `resolveRecipientLocale`(저장된 `UserPreference.locale`만 넘긴다) | 저장값이 없으면 `ko`                                 | `en`                         |

- `ko`·`en`은 어디서나 그대로다. 값이 없을 때 `ko`인 것은 언어를 보고하지 않던 옛 앱 사용자가 한국어 사용자였기 때문이다.
- `SUPPORTED_LOCALES`·`resolveSupportedLocale`(없음 `ko`, 지원하지 않는 언어 `en`)은 `@aido/api/vocabulary` 하나를 앱과 서버가 함께 쓴다.
- 예외는 `parseAcceptLanguage` 하나다. 지원하지 않는 요청 언어를 `ko`로 두는 것은 옛 `@Locale()` 동작을 지킨 호환이다(`request-client.spec`). 출시 앱은 `ko`·`en`만 보내 이 경로를 타지 않는다. 앱과 같은 `en`으로 맞추려면 `parseAcceptLanguage`가 `resolveSupportedLocale`을 쓰게 바꾸고 이 표를 고친다.
- 표시 언어는 글자만 바꾼다. 언어로 시간대·오늘·주 시작을 바꾸지 않는다.

## 카탈로그 (`@nestjs/i18n`)

- 위치: `apps/api/src/i18n/<locale>/<namespace>.json`. 지금 namespace는 `errors`·`notification`이고 기준 언어는 `ko`다. `nest-cli.json` `assets`로 dist에 복사한다.
- [AppI18nModule](../src/platform/i18n/i18n.module.ts)이 카탈로그를 읽는다(`responseHeaders: false`라 `Content-Language`·`Vary`를 붙이지 않는다). 패키지(0.0.x)는 `platform/i18n` 밖에서 직접 쓰지 않는다.
- 타입: `i18n-translations.ts`가 ko 카탈로그로 `declare module "@nestjs/i18n" { interface I18nTypes … }`를 등록한다. `catalog-parity.spec`이 언어 사이 키·자리표시자를 비교한다.
- 자리표시자는 `{name}`, 복수형은 CLDR 범주(`one`·`other`)다. 한국어 조사(을/를)는 `es-hangul` `josa`로 미리 붙여 인자로 넘긴다(`push/application/messages/locales/ko.messages.ts`).

## 문구별 규칙

| 문구            | 규칙                                                                                                                                                                                                                                                                                                                                       |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 오류 `message`  | `errors.json`에 `ErrorCode`별 문구. ko는 `Errors` 합니다체와 바이트 단위로 같고(`catalog-parity.spec`) en은 앱 `errors` 카탈로그의 영어와 같은 표현이다. `GlobalExceptionFilter`가 `ErrorMessageTranslator`로 기본 문구만 바꾸고, 던진 곳이 정한 문구와 검증 파이프 Zod 문구는 그대로 둔다. 코드를 더하면 ko·en에 함께 더한다              |
| 푸시            | `notification.json`(`<그룹>.<템플릿>.<variant>`). push slice가 같은 JSON을 import해(`notification-copy-catalog.messages.ts`) 요청 밖에서 수신자 언어로 렌더한다. ko 키가 다른 언어에 빠지면 컴파일 오류. 렌더 결과는 `notification-copy-render.messages.spec` 스냅숏으로 고정한다                                                          |
| 알림함 항목     | `copyKey`·`copyFacts`(언어와 무관한 원본 사실)를 저장하고 조회 때 `renderInboxCopy`가 요청 언어로 다시 렌더한다. `copyKey` 없는 옛 행·모르는 키·맞지 않는 사실·Accept-Language 없는 요청은 저장한 title·body다. 다른 Context가 만드는 알림도 `copyKey`·`copyFacts`를 넘겨야 언어를 바꾼 뒤 다시 렌더되고, 넘기지 않으면 저장 문구로 보인다 |
| 톤              | 앱 UI와 서버 푸시 모두 해요체, 이모지는 알림 하나에 최대 1개. 상세는 [푸시 알림](push-notifications.md#문구와-변형-선택)                                                                                                                                                                                                                   |
| Zod 검증 메시지 | 출시 계약이라 한국어 유지. 앱은 `SYS_0002`로 현지화                                                                                                                                                                                                                                                                                        |
| 메일            | `@nestjs/mail` `FileTemplateEngine`이 `email/infrastructure/templates/<이름>.<locale>.{html,txt}`(+ `layout`)를 렌더하고 제목은 `email-template.mapper.ts`가 만든다. 메일 발송 요청은 수신자 언어를 싣지 않아 `ko`로 렌더하고 `en` 파일은 ko와 같다. 언어를 받게 하려면 발송 payload에 언어를 더하고 `en` 템플릿을 채운다                  |
| AI 지시문       | ai-assistance 작업별 언어 파일(`<task>-system-{ko,en}.messages.ts`·`<task>-examples-{ko,en}.messages.ts`)과 `language-policy.messages.ts`. 기존 AI 평가를 통과할 때만 바꾼다([AI](ai.md#평가))                                                                                                                                             |
| 기간 라벨       | 앱이 `year`·`week`·`period`·`dateRange`로 직접 표시. 서버 필드는 호환으로 유지                                                                                                                                                                                                                                                             |

문구 자체를 바꾸는 일은 Before/After 표로 따로 올린다. 유입률을 바꾸는 카피 실험은 `ExperimentAssignerPort`로 나눠 측정한다([알림·지표](notifications.md#지표)).

## 언어 추가 절차

1. `@aido/api/vocabulary` `SUPPORTED_LOCALES`와 서버 `shared/domain/locale.ts`에 언어(예: `ja`)를 더한다.
2. `src/i18n/ja/*.json`과 push `locales/ja.messages.ts`를 만든다.
3. 메일 템플릿 `*.ja.{html,txt}`를 만든다.
4. 모바일 카탈로그를 만든다.

언어 짝 검사(키·자리표시자·복수 범주)가 빠진 곳을 실패로 알려 준다. `UserPreference.locale`은 문자열이라 마이그레이션이 없다. 렌더 결과는 스냅숏(`__snapshots__`)으로 바이트 단위로 확인한다.
