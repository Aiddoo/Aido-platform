# 다국어

서버가 만드는 문구(푸시·메일·오류 message·AI 지시문)를 더하거나 언어를 추가할 때 읽는다. 날짜·언어 공통 규칙은 [날짜·시간·언어](../../../docs/conventions/dates.md), 앱 문구는 [모바일 i18n](../../mobile/.claude/i18n-guide.md)에 있다.

## 언어 결정

| 상황                        | 결정                                                                                                           |
| --------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 요청 언어                   | `RequestClient`를 읽는 커스텀 `LocaleResolver` 하나. 헤더 정규화는 한 곳                                       |
| 수신자 언어(푸시·메일·배치) | `resolveRecipientLocale({ storedLocale, lastRequestLocale })`: 저장된 앱 언어 → 마지막 요청 언어 → 없음은 `ko` |
| 지원하지 않는 언어          | `en`(앱과 같다)                                                                                                |
| 값 없음                     | `ko`(언어를 보고하지 않던 옛 앱 사용자)                                                                        |

- `SUPPORTED_LOCALES`·`resolveSupportedLocale`은 `@aido/api/vocabulary` 하나를 앱과 서버가 함께 쓴다.
- 표시 언어는 글자만 바꾼다. 언어로 시간대·오늘·주 시작을 바꾸지 않는다.

## 카탈로그 (`@nestjs/i18n`)

- 위치: `apps/api/src/i18n/<locale>/<namespace>.json`. namespace는 Context 단위(`notification.json`, `errors.json`, `email.json`, `insights.json`)이고 기준 언어는 `ko`다. `nest-cli.json` `assets`로 dist에 복사한다.
- 타입: `ko` 카탈로그에서 키 타입을 만들어 `declare module "@nestjs/i18n" { interface I18nTypes { translations } }`로 등록한다. 없는 키·빠진 `count`는 컴파일 오류다.
- 요청 밖(푸시·메일·배치)은 `i18n.t(key, { lang: recipientLocale, args })`로 언어를 명시한다. `I18nContext.run`의 숨은 문맥을 쓰지 않는다.
- 자리표시자는 `{name}`, 복수형은 CLDR 범주(`one`·`other`)다. 한국어 조사(을/를)는 `es-hangul` `josa`로 미리 붙여 인자로 넘긴다. `select`가 필요해지면 공식 `formatter`(ICU)를 그때 더한다.
- 패키지 사용처는 어댑터 한 파일로 가둔다(0.0.x 공식 패키지라 API가 바뀔 수 있다).

## 문구별 규칙

| 문구            | 규칙                                                                                                                                                                       |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 푸시            | 문구는 `notification.json`(`<그룹>.<템플릿>.<variant>`), 조사·이름 표기는 `push/application/messages/locales/<locale>.messages.ts`. ko 키가 다른 언어에 빠지면 컴파일 오류 |
| 톤              | 앱 UI와 서버 푸시 모두 해요체, 이모지는 알림 하나에 최대 1개. parity spec이 검사한다                                                                                       |
| 오류 `message`  | `errors` namespace에 `ErrorCode`별 문구(ko는 기존 `Errors` 합니다체, en 추가). `GlobalExceptionFilter`가 요청 언어로 채운다. 계약은 문자열 그대로                          |
| Zod 검증 메시지 | 출시 계약이라 한국어 유지. 앱은 `SYS_0002`로 현지화                                                                                                                        |
| 메일            | 언어별 템플릿 파일(`welcome.ko.html`)                                                                                                                                      |
| AI 지시문       | 언어별로 복제하지 않고 한 벌에 `outputLanguage` 인자. 기존 AI 평가를 통과할 때만 바꾼다([AI](ai.md#평가))                                                                  |
| 기간 라벨       | 앱이 `year`·`week`·`period`·`dateRange`로 직접 표시. 서버 필드는 호환으로 유지                                                                                             |
| 알림함 항목     | `copyKey`·`copyFacts`(언어와 무관한 원본 사실)를 저장하고 조회 시 Accept-Language로 다시 렌더. 키 없음·모르는 키·헤더 없음은 저장 문구                                     |

문구 자체를 바꾸는 일은 Before/After 표로 따로 올린다. 유입률을 바꾸는 카피 실험은 `ExperimentAssignerPort`로 나눠 측정한다([알림·지표](notifications.md)).

## 언어 추가 절차

1. `@aido/api/vocabulary` `SUPPORTED_LOCALES`에 언어(예: `ja`)를 더한다.
2. `src/i18n/ja/*.json`을 만든다.
3. 메일 템플릿 `*.ja.html`을 만든다.
4. 모바일 카탈로그를 만든다.

언어 짝 검사(키·자리표시자·그 언어에 필요한 복수 범주)가 빠진 곳을 실패로 알려 준다. `UserPreference.locale`은 문자열이라 마이그레이션이 없다. 카탈로그로 옮길 때는 푸시 문구 스냅샷(`__snapshots__`)으로 렌더 결과가 바이트 단위로 같은지 확인한다.

## 전환 중

- 오류 `message`는 카탈로그로 옮겼다. [AppI18nModule](../src/platform/i18n/i18n.module.ts)이 `src/i18n/<locale>/errors.json`을 읽고 `RequestClientLocaleResolver`가 `resolveResponseLocale`(RequestClient와 같은 헤더 정규화)로 요청 언어를 정한다. `GlobalExceptionFilter`는 `ErrorMessageTranslator`로 코드의 기본 문구만 바꾸고, 던진 곳이 정한 문구와 Nest `HttpException`(검증 파이프 Zod 문구 포함) message는 그대로 둔다. 응답 헤더(`Content-Language`·`Vary`)는 붙이지 않는다.
- ko `errors.json`은 `Errors` 문구와 바이트 단위로 같아야 한다(`catalog-parity.spec`). 오류 코드를 더하면 ko·en 카탈로그에 함께 더한다. en 문구는 앱 `errors` 카탈로그의 영어 문구와 같은 표현을 쓴다.
- 푸시 문구는 `src/i18n/<locale>/notification.json`으로 옮겼다. 팩토리(`create*NotificationMessage`)가 `copyKey`·`copyFacts`를 함께 돌려주고 notification Context의 알림 생성은 둘을 저장한다. 다른 Context가 만드는 알림은 아직 저장 문구만 쓴다. 렌더 결과는 `notification-copy-render.messages.spec` 스냅샷(모든 템플릿·variant·언어)으로 고정한다.
- 알림함(`GET /v1/notifications`·`/inbox`)은 `renderInboxCopy`가 `renderNotificationCopy`로 요청 언어 문구를 만든다. `copyKey`가 없는 옛 행, 렌더가 `null`(모르는 키·맞지 않는 사실)인 행, Accept-Language가 없는 요청은 저장한 title·body를 준다.
- 메일은 `@nestjs/mail` `FileTemplateEngine`이 email slice `infrastructure/templates/<이름>.<locale>.{html,txt}`(+ `layout`)를 렌더하고 제목은 `email-template.mapper.ts`가 만든다. 수신자 언어를 아직 받지 않아 모두 `ko`로 보내며 `en` 파일은 ko와 같다(`nest-mail-email-templates.adapter.spec` 스냅숏). AI 지시문은 언어별 파일이다. 저장용 locale(`parseAcceptLanguage`, `shared/domain/locale.ts`)은 지원하지 않는 언어를 `ko`로 본다. 카탈로그 전환은 각 Context를 옮길 때 그 Context 문구만 한다.
