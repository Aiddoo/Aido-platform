# Native dependency patches

| Package                           | Version   | Purpose                                                                                                                                                                                                                                                                                                                                                                                       | Removal condition                                                                                                                       |
| --------------------------------- | --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `expo-widgets`                    | `58.0.10` | Android widget root taps launch the installed app through `actionStartActivity`. The JavaScript interaction callback alone cannot cold launch the app. The layout registry CLI resolves its entry symlink so pnpm Android builds generate the required resource. Provider lookup uses SDK manifest metadata to preserve legacy components, and snapshot writes serialize with cold migration. | Expo provides native app launch support, fixes the CLI entry guard, and supports metadata-based providers with atomic migration writes. |
| `@sentry/react-native`            | `8.28.0`  | Expo Router 58 removed the private router store. Return the SDK's existing unsupported-router fallback directly so Metro does not resolve the missing optional import. Error capture, masked replay, and native SDK behavior remain unchanged.                                                                                                                                                | Upstream removes the missing import or supports Expo Router 58 through compatible APIs.                                                 |
| `@gorhom/bottom-sheet`            | `5.2.14`  | Existing gesture builders and relationships use Gesture Handler 3's `LegacyPanGesture`, `LegacySimultaneousGesture`, and `LegacyTextInput` exports consistently.                                                                                                                                                                                                                              | Upstream supports Gesture Handler 3 or migrates the entire gesture relationship group.                                                  |
| `react-native-draggable-flatlist` | `4.0.3`   | Existing gesture builders retain compatible `LegacyFlatList` and `LegacyScrollView` wrappers under Gesture Handler 3. Removed React Native `InteractionManager` resets use cancellable idle callbacks. Nested layout measurement uses `getNativeScrollRef()` instead of numeric tags, as required by React Native 0.88 host refs.                                                             | Upstream supports Gesture Handler 3's new gesture API.                                                                                  |

The gesture patches cover source, compiled module/CommonJS entry points, and declarations. They do not change gesture behavior. HeroUI Native 1.0.10 still declares Gesture Handler 2 as a peer; its legacy builders are retained, and the peer override is maintained in `.pnpmfile.cjs`. This is a compatibility adaptation rather than an upstream support claim. Recheck drag gestures, nested scroll views, bottom-sheet inputs, and Android/iOS gestures when upgrading any of these dependencies.

Android widget refresh metadata is set by `apps/mobile/plugins/withWidgetRefreshInterval.js`; it is separate from the cold-launch patch. Keep the iOS widget name and App Group unchanged. `withAndroidWidgetCompatibility.js` retains the three legacy receiver components through SDK subclasses and reads old MMKV snapshots without modifying them. The APK upgrade harness verifies preservation, SDK rendering/refresh, safe malformed-data fallback, and concurrent account writes.

References: [Gesture Handler 3 migration](https://docs.swmansion.com/react-native-gesture-handler/docs/guides/upgrading-to-3/), [Expo Widgets](https://docs.expo.dev/versions/latest/sdk/widgets/), [Glance interactions](https://developer.android.com/develop/ui/compose/glance/user-interaction), [Node ESM filename resolution](https://nodejs.org/download/release/latest-v24.x/docs/api/esm.html#importmetafilename).

Sentry 8.28.0 is the Expo SDK 58 recommended version. Sentry 8.29.0 still references the removed store. The app does not enable navigation tracing; this patch does not implement Expo Router automatic route attribution. Keep tracing disabled until an upstream-compatible integration is available. The patch touches the published JavaScript entry only and requires no native dependency change. References: [Expo bundled versions](https://github.com/expo/expo/blob/main/packages/expo/bundledNativeModules.json), [Sentry router helper](https://github.com/getsentry/sentry-react-native/blob/8.28.0/src/js/tracing/expoRouterStore.ts), [Sentry 8.29.0 release](https://github.com/getsentry/sentry-react-native/releases/tag/8.29.0).
